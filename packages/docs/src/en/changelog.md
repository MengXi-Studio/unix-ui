# Changelog

## [0.5.0] - 2026-11-13

Added the m-color-picker trio, the m-fab / m-fab-item floating action button components, the four m-checkbox components, m-date-strip and the date utility toolkit.

### Added

- **m-color-picker / m-color-picker-popup / m-color-picker-input color picker trio**: m-color-picker offers a saturation-brightness panel plus a hue slider (`show-alpha` adds an alpha track and the A component), with a controlled string `v-model:value` and `format` supporting `hex` / `rgb` / `hsl` (hex with alpha outputs 8-digit `#RRGGBBAA`; incoming values accept `#RGB` / `#RGBA` / `#RRGGBB` / `#RRGGBBAA` / `rgb()` / `rgba()` / `hsl()` / `hsla()`); `show-format` switches formats in place, `presets` / `show-presets` render preset swatches (built-in colors when omitted), `show-inputs` adds R/G/B/A numeric inputs (commit on blur, clamped), `show-recent` keeps up to 8 recent colors (recorded on gesture end or selection), and `show-eyedropper` enables the Web-only eyedropper (`#ifdef WEB`, Chromium EyeDropper; the entry is not rendered elsewhere). Because App `background-image` supports a single `linear-gradient` only, the panel stacks three absolutely positioned layers (solid hue + horizontal white + vertical black). m-color-picker-popup has a cancel / title / confirm header plus an internal draft (confirm writes back and closes; cancel and overlay close discard), and applies live when `show-confirm=false`; m-color-picker-input is a readonly trigger with a left color swatch, optional field label, custom clear button and popup selection; new `$m-color-picker-*` theme variables (see [ColorPicker](/en/components/color-picker))
- **m-checkbox-group / m-checkbox / m-checkbox-popup / m-checkbox-input checkboxes**: m-checkbox-group is the multi-select container (`v-model:value` is an `Array<string | number>` union array, verified to compile on all targets; `'1'` equals `1` via stringified comparison), distributing shape / checked-color / icon-size / disabled / max / direction to items (overridable per item); m-checkbox is dual-form (joins the group by name, or stands alone with a boolean `v-model`), with square shape, label-position swap, label-disabled (icon still clickable), an indeterminate dash, icon / default slots (scoped `{ checked, disabled }`), and an exposed `toggle()` for whole-row cell toggling; m-checkbox-popup is a bottom sheet (options-driven rendering + field-names mapping + footer slot); m-checkbox-input is a readonly trigger + popup (labels join with 「、」, over 2 items collapse to "N items", custom clear button); new `$m-checkbox-*` theme variables (see [Checkbox](/en/components/checkbox))
- **m-fab / m-fab-item floating action button**: a round entry button pinned to a viewport position expands a list of action buttons on click and collapses after one is tapped; four-corner positioning (`top` / `right` / `bottom` / `left`, theme default offset when omitted, expanding downward when the entry sits in the upper half of the viewport); `background` / `color` customize the entry and item colors (gradients supported, items inherit the container values when omitted); `hide-name` hides the names; the `entry` slot customizes the entry content (scoped `visible`) and the `name` slot customizes the labels; `overlay-closable` renders an overlay while expanded and closes on tap; `draggable` dragging (`axis` with four values, `margin-x` / `margin-y` boundary clamping, `magnet` snapping to the nearest edge on release, `v-model:offset` controlled position reported as the entry center coordinates); expand / collapse are per-item inline transitions (staggered by registration order, reversed on collapse); new `$m-fab-*` theme variables (see [Fab](/en/components/fab))
- **m-date-strip date strip**: a horizontally scrollable strip of consecutive dates (default: 7 days before through 7 days after today) with `type` supporting `single` / `multiple` / `range`; selection applies immediately with no confirm button. `v-model:value` binds strings when `value-format` is set (converted through `parseDate` / `formatDate`; invalid strings are treated as unselected). `max-range` rejects over-limit selections and emits `over-range` (naming follows m-calendar; no toast is shown); `allow-same-day` permits single-day ranges and endpoint labels are customizable via `start-date-text` / `end-date-text` / `same-date-text`; `disabled-date` greys out dates and emits `click-disabled-date`, while `filter` hides dates entirely; `show-lunar` renders lunar text below the day number (reusing `solarToLunar` + `getLunarDateText`); `formatter` keeps the `CalendarDayItem` contract, plus `item` / `top-info` / `bottom-info` scoped slots; the selected item is centered on mount and on external value changes; new `$m-date-strip-*` theme variables (see [DateStrip](/en/components/date-strip))
- **Date utility toolkit**: adds `packages/core/utils/date.uts` as the public entry, layered into seven pure-function modules under `utils/date/` (core / compare / arith / boundary / grid / format / lunar) with 69 named exports — primitives (normalization / validation / timestamps / leap years / month length / day of year), comparison (same day / month / before / after / between / today / weekend), arithmetic and diffs, week / month / year boundaries and interval enumeration, a fixed 6×7 month grid plus week numbers and quarters, formatting and parsing (13 baseline tokens plus `W` / `Q` / `A` / `a`, `[]` literal escaping, validated parsing that rejects overflow), and full 1900-2100 lunar conversion (leap months as negatives) with sexagenary / zodiac / month / day / hour names; everything is immutable, uses local midnight and returns `null` on failure; m-calendar's shared date helpers now come from the toolkit and are re-exported by `calendar.uts` to keep old import paths working (see [Date](/en/tools/date))

### Fixed

- **m-tabs options mode: the independent bottom line is not positioned on first paint** ([#10](https://github.com/MengXi-Studio/unix-ui/issues/10)): the options form has no `m-tab` children, so `ctx.items` stays empty and the `animateLine` call inside `watch(ctx.items)` never runs; because the initial `activeIndex` equals the `resolveActive` result, `watch(activeIndex)` does not fire either, leaving `lineLeft` at 0 and the line stuck at the far left until the user taps a tab. `onMounted` now performs one `nextTick` positioning pass after resolving the initial active index and initializing the render set (`firstSet` places it directly without animation), measuring synchronously on Web and querying by id asynchronously on Mini Program after nodes render, so there is no first-frame flicker
- **m-popup: no slide-in animation on the second and later opens on WeChat Mini Program** ([#11](https://github.com/MengXi-Studio/unix-ui/issues/11)): the non-Web `triggerPanelIn` used `nextTick` to switch to the entered state, but the Mini Program renderer batches two setData calls made too close together, so the panel's starting position (`-out`) was merged with the overlay's `display:none` removal into a single paint, leaving the transition without a starting frame; the panel then appeared directly at its final position from the second open onward (the first open worked because `lazyRender` mounts the panel and paints the starting position in the mount frame). It now uses the same 50ms delay as m-overlay's fade-in so the starting position is painted first; the Web double-rAF branch is unchanged

## [0.4.2] - 2026-11-12

Fixes the m-tabs WeChat Mini Program crash at mount for `canScroll` instances ([#8](https://github.com/MengXi-Studio/unix-ui/issues/8)), restoring active-tab centering in the scrollable layout, standalone bottom-line positioning with nav slots, and the scrollspy judgment / click positioning on Mini Program; hides the horizontal scrollbar of the scrollable tab bar on Web.

### Fixed

- **m-tabs shows a horizontal scrollbar on the scrollable tab bar on Web**: when 0.4.1 fixed the broken scrolling it restored `overflow-x: auto` on the inner scrolling layer, and the browser's default scrollbar appeared with it. Investigation shows the uni-h5 runtime's `show-scrollbar="false"` only appends a `uni-scroll-view-scrollbar-hidden` class to the inner scrolling layer, while the CSS that hides the scrollbar is missing from the runtime stylesheet altogether (`::-webkit-scrollbar` has zero occurrences in both the vapor and VDOM builds), making the prop a no-op on Web. Two fixes: the tab bar scroll-view sets `:show-scrollbar="false"` explicitly (effective on App semantics); on Web the component hides it internally under `#ifdef WEB` — `scrollbar-width: none` plus `::-webkit-scrollbar` covering the real inner scrolling layer (the wrapper node is not a template node, so a descendant selector is required; compiled only for Web, unconstrained by the App-side ucss descendant-selector limitation). Verified that the scrollbar occupies zero height while horizontal scrolling keeps working
- **m-tabs throws `Cannot read properties of undefined (reading 'length')` on mounted on WeChat Mini Program, leaving no active tab on first paint** ([#8](https://github.com/MengXi-Studio/unix-ui/issues/8)): on Mini Program the `UniElement` has neither `children` nor `parentElement` (no subtree or ancestor traversal at all), so `findDescendantById`'s `el.children.length` and `findScrollParent`'s ancestor walk crash right at mounted for any `canScroll` instance (shrink or tab count over the threshold), interrupting active-state initialization; meanwhile `getBoundingClientRectAsync` only works on elements that carry an id (its internals are `createSelectorQuery().in($vm).select('#id')`, scoped to the component instance and therefore multi-instance safe). Three fixes: `findDescendantById` / `findScrollParent` return null at compile time on Mini Program (call sites already guard with null checks and degrade gracefully); the nav / bottom line / root / content panes get ids (m-tab panes use a dynamic id derived from their registration order), and a `queryRectById` helper is added (`uni.createSelectorQuery().in(instance.proxy)` — id-scoped lookup inside the component instance) so active-tab centering in the scrollable layout, standalone bottom-line positioning with nav slots, and the scrollspy judgment and click positioning are all restored on Mini Program; the bottom-line switch animation degrades to a direct landing on Mini Program (`UniElement.animate` transform-keyframe support is unverified there), and inside an embedded scroll-view the scrollspy judgment and click positioning fall back to the page-level scrolling semantics (`pageScrollTo`)

## [0.4.1] - 2026-11-12

Fixes the m-tabs underline offset in scrollable / shrink layouts, the WeChat Mini Program first-paint failure, the broken active-tab centering in the scrollable layout, the underline offset with nav slots, and the broken scrollspy click-to-scroll.

### Fixed

- **m-tabs active underline is offset by half its width in scrollable / shrink layouts**: when the tab count exceeds `swipe-threshold` (scrollable layout) or with `shrink`, the active underline is the title-embedded line whose `left: 50%` pins only the line's left edge without pulling back its own half width, shifting the whole line right by half of `line-width` (20px with the default 40px); the standalone bottom line of the equal-width layout is unaffected. A `transform: translateX(-50%)` centering pullback is added (translateX percentages resolve against the element's own width on every platform and adapt to any `line-width`)
- **m-tabs throws TypeError on mounted on WeChat Mini Program, leaving no active tab on first paint**: on Mini Program the `UniElement` only exposes the async `getBoundingClientRectAsync` and has no synchronous `getBoundingClientRect`, so the component throws `TypeError: el.getBoundingClientRect is not a function` in `measureWidth` right at mounted, and the rest of the same hook (active-state initialization) never runs — first paint shows no active tab and no bottom line. Three fixes: `measureWidth` only measures in the freeLine layout (standalone bottom line) and `swipeable` (track translation / gesture threshold) scenarios (selfWidth is not consumed elsewhere), App / Mini Program go through the async API while Web keeps the synchronous measurement (platform branches aligned with m-sticky); the `scrollspy` scroll-driven activation and click-to-scroll are likewise split per platform (on Mini Program all panes are measured asynchronously in a batch and then judged together). Web behavior unchanged ([#5](https://github.com/MengXi-Studio/unix-ui/issues/5))
- **m-tabs scrollable nav cannot scroll and the active tab is never centered**: the nav scroll-view still used the deprecated `scroll-x` prop (uni-app x replaced it with `direction`, defaulting to `vertical`); with only `scroll-x` set, the inner scrolling layer keeps `overflow-x: hidden`, so horizontal touch scrolling and programmatic `scroll-left` / `scroll-into-view` all do nothing and the active tab stays clipped at the edge. On top of that, the title row (a view, which defaults to `overflow: hidden`) clips the overflowing titles inside itself, so the scroll-view's scrolling region never sees the overflow (`scrollWidth == offsetWidth`) and every programmatic scroll target gets clamped to 0 even with `direction` fixed. Three fixes: `:scroll-x` becomes `:direction` (`horizontal` when scrollable); the title row gets `overflow: visible` (clipping is handed back to the scroll-view's real scrolling layer); `scroll-into-view` is removed (it can only align an element's start edge, so the last tab would stay clipped) in favor of programmatic centering — the active title element is located by id via depth-first search (the Web scroll-view renders compiler-internal wrappers, so direct-child structure cannot be assumed), the delta between title center and viewport center is measured and applied through the `scroll-left` prop (an `@scroll` handler mirrors the actual position back so a same-value target re-triggers after manual scrolling), out-of-range targets are clamped by the scroll-view itself, and `scroll-with-animation` smooths the centering. m-cascader's level tabs row is fixed the same way (`scroll-x` → `direction="horizontal"` plus row `overflow: visible`, restoring level `scroll-into-view`)
- **m-tabs standalone underline is offset when nav slots are present**: the equal-width layout positioned its standalone bottom line with the uniform-slot formula `(i + 0.5) * container width / tab count`; once `nav-left` / `nav-right` slots take up space, the real title center diverges from the slot center (measured about half a line width off to the left). It now switches to measurement-based positioning — the active title element is located by id via depth-first search and measured, with the measurement baseline unified to the bottom line's positioning parent (the nav origin, strictly matching the render origin `left: 0 + translateX`; the line and the title row live in different subtrees of the nav, and mismatched baselines amplify the offset). First activation lands directly, switches animate via `UniElement.animate`, and the behavior is insensitive to slot presence or the scrollable title row
- **m-tabs scrollspy click does not scroll and activation desyncs from content**: the click handler called `scrollTo`, which is only a property name in the `defineExpose` object literal rather than a component function — in Web builds the bare call resolves to the global `window.scrollTo` (the index is treated as a scroll coordinate), which is a complete no-op on pages scrolling inside a scroll-view and raises no error. It now calls `scrollToIndex`. The baseline semantics of click positioning and the scrollspy judgment are also unified to "the bottom edge of the stuck tab bar" (scrollport top + `offset-top` + tab bar height) — the judgment previously used `offset-top` directly, which in scroll containers with a non-zero viewport offset (e.g. a fixed page navbar on top) shifted the whole baseline by the container offset, showing an active tab that disagrees with the on-screen content; the baseline is derived from the stable quantities container top offset + `offset-top` + tab bar height, decoupled from the m-sticky attach timing (the attach state may not have switched yet when the scroll event triggers the judgment, so the tab bar's live rect cannot be used)

## [0.3.1] - 2026-11-09

WeChat Mini Program adaptation fixes: m-overlay visibility and transition timing, m-icon font loading.

### Fixed

- **m-overlay overlay visibility broken on Mini Program**: the root `v-show` is compiled by the uni-app x compiler into a `virtualHostHidden` expression that gets short-circuited by the external default `false`, so hidden transparent full-screen overlays stayed on top intercepting every touch and no button on the page was clickable; the root `v-show` is removed and the hidden state now appends `display: none` at the end of rootStyle (placed after custom-style to override its display declaration). The root `v-if` remains unusable (on the uni-app x Web runtime, event bindings passed through attrs are lost when the root node switches from a comment node to a created node), and popup components composed on m-overlay such as m-popup are fixed on Mini Program accordingly
- **m-overlay fade without a gradual appearance on Mini Program**: the Mini Program render layer merges two setData updates that fire too closely into a single paint — the opacity 1 set after nextTick (a logic-layer microtask) gets merged with the display removal into the same paint, so the transition has no starting point and the overlay just pops in; the non-Web show trigger changes from nextTick to a 50ms timeout to stagger the timing (ensuring the first frame after the display:none removal has finished painting; 50ms is imperceptible within a transition starting at 0.3s), while the Web double-rAF timing is unchanged
- **m-icon font loading failure on WeChat Mini Program**: `@font-face` in wxss does not support local font file paths (Web / App are unaffected), so icons all rendered as default glyphs; on MP-WEIXIN the in-style `@font-face` declaration is excluded via conditional compilation and replaced by a runtime `uni.loadFontFace` call in onMounted (`global: true` to apply to all pages) loading a base64 inlined font (new `m-icon-font.uts`, font data bundled in the package with zero configuration); icons may flash with default glyphs on the first frame, which is a known limitation

## [0.3.0] - 2026-11-05

Adds the flex layout components (m-flex / m-flex-item), the status bar placeholder component (m-status-bar), the sticky layout components (m-sticky / m-sticky-box), the waterfall components (m-waterfall / m-waterfall-item / m-waterfall-load) and the cascader family (m-cascader / m-cascader-popup / m-cascader-input, form family).

### Added

- **m-cascader / m-cascader-popup / m-cascader-input cascader family**: split into three components by "panel / popup / input" — m-cascader pure inline panel (header + level tabs + swiper-hosted level option lists, `v-model:value` leaf value of the `string | number` union type, options as the dynamic type `UTSJSONObject[]` supporting `field-names` mapping and async loading (modifying children inside the change callback re-renders automatically; an empty array is treated as a leaf and finishes directly), `swipeable` gesture level switching (hosted by disable-touch), `active-color` theme color derivation, `options-height` options area height (prop overrides the theme variable), closeable / close-icon / show-header header capabilities; change / finish / close / click-tab events and the four slots title / option / options-top / options-bottom, external `value` rebuilds the path from the options tree with a guard against v-model write-back loops); m-cascader-popup popup cascader composed on m-popup (full popup props pass-through, auto close after finish, `v-model:value` controlled value pass-through, conditional forwarding of cascader events and the four slots, header close icon uniformly closes via update:show); m-cascader-input composed of an m-input readonly trigger + popup (`v-model:value` write-back on finish, path text joined with "/" for display (falls back to the value string when the path is not found), self-drawn clear button, disabled / border / inlaid forms, full pass-through of field-names / options-height / swipeable); adds the `$m-cascader-*` and `$m-cascader-input-*` theme variable sections (see [Cascader](/en/components/cascader))
- **m-flex / m-flex-item**: four `direction` values (row / row-reverse / column / column-reverse, equivalent to flex-direction), three built-in `gap` sizes (small / medium / large mapped to `$m-flex-gap-sm` / `$m-flex-gap` / `$m-flex-gap-lg`) plus custom sizes (number gets a px suffix / string used as is), four `align` values (equivalent to align-items; baseline falls back to flex-start on App), six `justify` values (equivalent to justify-content, adding between / around / evenly), a `flex` CSS shorthand pass-through, `wrap` auto wrapping (row / row-reverse only) and a default slot; spacing is implemented via the margins of m-flex-item (flex `gap` is not supported by ucss on App), with items sensing their position through provide/inject + reactive registration order — non-first items in row and non-last items in row-reverse get `margin-left`, non-first items in column get `margin-top`, non-last items in column-reverse get `margin-bottom` (reversed directions leave no extra space at either end); when wrapping horizontally every item gets `margin-left` with an equal negative margin on the container (all lines start flush) and the line spacing is the item's `margin-bottom` (an extra spacing below the last line is a known limitation); unwrapped children do not participate in spacing, and standalone use of m-flex-item degrades to an ordinary vertical container
- **m-status-bar placeholder**: reserves the system status bar height for top-anchored elements such as Navbar / Notify; the `height` prop (px, used directly when greater than 0) takes precedence, otherwise the App platform reads `uni.getWindowInfo().statusBarHeight` automatically while Web / Mini Program stay at 0 (no placeholder); `custom-class` / `custom-style` direct styling (background etc.), no dedicated theme variables; the playground demo-navbar now consumes this component
- **m-sticky (controlled sticking on every platform)**: the page passes `scroll-top` from the scroll container's `@scroll` event, and the component walks up `parentElement` to locate the nearest scroll container (by the `uni-scroll-view` class on Web, by "scroll height greater than visible height" on App / Mini Program) and uses its visible area as the sticking reference; when stuck the content node switches to `position: fixed` while the root keeps the measured placeholder height so the layout does not collapse. **Native CSS `position: sticky` is not used**: the uni-app x Web runtime injects `overflow: hidden` into every `view`, so the nearest scroll container of sticky degenerates into a non-scrolling parent and never sticks (verified: rect.top stays at -198 after scrolling 400px). `position` (top / bottom) with mutually exclusive `offset-top` / `offset-bottom` (relative to the scroll container's visible edge, so a custom navbar needs no extra offset), `z-index` (99 by default via the theme class, overridden inline only when non-default), `custom-class` / `custom-style` (attached to the content node), and `change(isFixed)` / `scroll({ scrollTop, isFixed })` events; measured only on first render and re-measured on window resize, so content size changes require rebuilding the component (no `refresh()`)
- **m-sticky-box container boundary**: provide/inject hands an inner m-sticky the container `UniElement` reference so the sticky element stops at the container's top / bottom edge (container visibility check and translateY compensation); the container needs an explicit height to create the sticky travel range; adds the theme variable `$m-sticky-z-index: 99 !default`
- **m-waterfall / m-waterfall-item / m-waterfall-load**: the container measures its available width and divides it into columns; each item measures its own height at the correct width and reports it back, then the container computes absolute positions (left / top / width) with "registration order → shortest column first" and writes back the total height. Layout is strictly sequential (later items stay hidden while an earlier one is still loading, so placed items never jump), and unloaded items reserve their correct column width with `visibility: hidden` so heights are measured accurately. `columns` (2 by default), `column-gap` / `row-gap` (px, 16 by default), `custom-class` / `custom-style`; the item slot exposes `onLoad` (call when content finishes loading to re-measure) and `columnWidth`; `loadstart` / `load` events plus `reflow()` / `onLoad(handler)` instance methods; `m-waterfall-load` reserves height from width / height via `padding-top`, uses the natural image size when loaded within `max-wait`, keeps the custom ratio after a timeout and exposes `overtime`. There is no ResizeObserver (the width is measured on mount / window resize / reflow), and horizontal padding on the container eats into column width (put gutters on an outer wrapper)

### Fixed

- **VDOM Web runtime TS diagnostic WARNING cleanup (32 prop types)**: a nullable prop declared `T | null` with a null default made the compiler emit props as `type: [T, null]` (rejected by Vue's Prop typings), producing `No overload matches this call` noise that also leaks into end users' runtime logs; nullable props now drop the `| null` annotation while **keeping `default: null`** (the runtime value is still null when omitted — three-state semantics and behavior unchanged) — covering `value` / `minDate` / `maxDate` / `defaultDate` / `formatter` / month `panel` on m-calendar, the same set on m-calendar-popup, `value` / `minDate` / `maxDate` on m-calendar-input, `offset` on m-col, `justify` / `align` on m-row, `gutter` / `columnNum` / `iconSize` on m-grid, `icon` / `gutter` on m-grid-item, `width` / `height` / `radius` on m-image, `size` / `align` on m-space, `formatter` / `precision` / `min` / `max` on m-input, `icon` / `clickable` on m-cell, `type` / `position` / `icon` / `forbidClick` / `loadingType` / `duration` / `wordBreak` on m-toast, and `beforeClose` on m-popup; the remaining 3 SSRSlot WARNINGs come from the generated code of conditional slot forwarding and are compiler typing noise with no runtime impact

## [0.2.0] - 2026-11-03

Adds the popup-family base components (m-overlay / m-popup), the divider component (m-divider), the grid components (m-grid / m-grid-item), the toast component (m-toast, feedback family), the compact layout component (m-compact, layout family), the input component (m-input, form family) and the calendar component family (m-calendar / m-calendar-popup / m-calendar-input, form family), bringing the total to 18 base components.

### Added

- **m-overlay**: `show` visibility, `z-index` level, `duration` in seconds (`0` disables animation), `custom-class` / `custom-style` direct styling and a `click` event (the overlay does not close automatically); built-in body scroll lock on Web (released only when all stacked instances close), the foundation of popup components
- **m-popup**: five positions (center / top / bottom / left / right), per-side round corners, closeable with `close-icon` / `close-icon-position`, `close-on-click-overlay`, overlay customization (`overlay` / `overlay-class` / `overlay-style`), `z-index` / `duration`, `lazy-render` / `destroy-on-close`, `safe-area-inset-top` / `safe-area-inset-bottom`, and a `before-close` guard (sync boolean); `v-model:show` two-way binding with full events (open / opened / close / closed / click / click-overlay / click-close-icon); center scales in with a fade, edge positions slide, composed on top of m-overlay
- **m-divider**: horizontal / vertical forms (vertical as a flex item; parent container needs `flex-direction: row` + `align-items: center`), `dashed`, `hairline` 0.5px thin line (1px border + single-axis 0.5 scale, safe on App platforms), `content-position` (left / right / center, one line width-capped at 10%), default slot with inherited text styles
- **m-grid / m-grid-item**: `column-num` custom columns, `square` cells (percentage padding-top + absolutely positioned content), `gutter` spacing (same value for rows / columns, evenly distributed per the m-row precedent), `border` full table borders (container draws the top + left lines, items draw the right + bottom lines), `center` content centering, `direction` horizontal layout, `reverse` icon-text swap, `clickable` press feedback (native view hover-class); per-item `text` / `icon` / `icon-color`, `dot` / `badge` (via m-badge), `click` events and `url` in-app page navigation, with default / icon / text slots
- **m-toast**: imperative API (`showToast` / `showSuccessToast` / `showFailToast` / `showLoadingToast` / `closeToast`, string shorthand or ToastOptions object, singleton semantics) and component usage (`v-model:show` + default slot); `type` (text / loading / success / fail), `position` (top / middle / bottom), custom `icon`, `overlay` / `forbidClick` masking and click interception, `closeOnClick` / `closeOnClickOverlay`, `duration` (loading defaults to 0, no auto close), `wordBreak` wrapping control (normal / break-all on all platforms; break-word is Web / Mini Program only, App falls back to normal), `onOpened` / `onClose` callbacks and opened / close events; built on the "global functions + page-level container + global singleton bridge" approach (uni-app x has no runtime dynamic mounting)
- **m-compact**: wraps m-button so adjacent items join their corner radii and merge neighboring borders into 1px, with variant mixing supported; `block` fills the parent width (horizontal `flex: 1` even split / vertical full width, no need to set block per button), `direction` horizontal / vertical; first / middle / last positions recalculated automatically when children are added or removed via `v-if` / `v-for`; the 0.5px hairline scale layer clears the corresponding side radii and borders in sync; position sensing is built on provide/inject + reactive registration order (ucss has no `:first-child` structural selectors), no dedicated theme variables (radii / borders reuse the `$m-button-*` family, see [Compact](/en/components/compact))
- **m-space-item**: the wrapper component for m-space children; spacing is implemented via its margins — flex `gap` is not supported by ucss on App, where the gap declaration was silently dropped by the compiler, breaking spacing; each item senses its position via provide/inject + reactive registration order (reusing the m-compact precedent); in the horizontal direction every item gets margin-left with an equal negative margin on the container (all wrapped lines start flush), in the vertical direction non-first items get margin-top, and in wrap scenarios the line spacing is the item's margin-bottom (an extra spacing at the bottom of the last line is a known limitation); unwrapped children do not participate in spacing, and standalone use degrades to an ordinary vertical container (see [Space](/en/components/space))
- **m-input**: six types (text / tel / digit / number / password / textarea), `clearable` + `clear-trigger` dual timing (focus / always), `maxlength` (-1 for unlimited) + `show-word-limit` character counting, `border` / `inlaid` (strips border and padding for cell embedding), `disabled` / `readonly` (readonly simulated via disabled, no native support), `confirm-type`, textarea `auto-height`; `formatter` + `format-trigger` (onChange / onBlur), `precision` with trailing zeros kept, `min` / `max` blur-time numeric clamping, `show-eye` plaintext toggle; prepend / append slots, `v-model` unified as string with input / change (blur-time snapshot comparison) / focus / blur / clear events, exposed `focus()` / `blur()` methods; injects the m-compact context to mix with m-button (see [Input](/en/components/input))
- **m-calendar / m-calendar-popup / m-calendar-input**: split into three components by "panel / popup / input" — m-calendar is a pure inline panel (three selection types single / multiple / range, `switch-mode` year-month navigation clamped to the selectable range, `formatter` day customization, `first-day-of-week`, `row-height`, month watermark, `height` panel height, `color` theme color deriving the selected dot and range bar (gradients supported), `min-date` / `max-date` out-of-range disabling, `max-range` over-range limit shared by range and multiple (rejected + `over-range` + m-toast prompt), `allow-same-day`, `default-date` pre-selection; select / confirm / unselect / over-range / month-show / panel-change / click-subtitle / click-disabled-date events with 12 slots; exposed `reset()` / `resetSelection()` / `scrollToDate()` / `getSelectedDate()` / `refreshView()` methods); m-calendar-popup is a popup calendar composed on m-popup (popup props fully forwarded plus `popup-height` percentage conversion, auto-close on confirm, `refreshView` resetting the focused month on reopen, `v-model:value` controlled selected value forwarding, `reset-on-open` resetting the selection to value / default-date on open, calendar events and slots conditionally forwarded); m-calendar-input is composed of an m-input read-only trigger plus the popup (`v-model:value` write-back on confirm, single value / range span / multiple joined text display, self-drawn clear button, disabled / border / inlaid trigger forms, inner selection resetting to the current value on popup open (`reset-on-open` enabled internally)) (see [Calendar](/en/components/calendar))

## [0.1.0] - 2026-10-27

First usable release: a UI component library for uni-app x with a pnpm monorepo architecture (core / docs / playground), one set of UTS + uvue sources covering multiple platforms, with 9 built-in base components.

### Added

- **m-button**: five types (default / primary / success / warning / danger), four sizes (large / normal / small / mini), plain, round, square, block, disabled, loading state (loading / loading-text, the loading icon is powered by [m-loading](/en/components/loading), `loading-type` supports `circular` / `spinner`), press feedback (hover-class based, opacity overridable via `$m-button-active-opacity`), custom color (color, supporting `linear-gradient` gradients) and hairline borders
