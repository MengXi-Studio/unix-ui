# Changelog

## [0.4.1] - 2026-11-11

Fixes the m-tabs underline offset in scrollable / shrink layouts and m-tabs on WeChat Mini Program.

### Fixed

- **m-tabs active underline is offset by half its width in scrollable / shrink layouts**: when the tab count exceeds `swipe-threshold` (scrollable layout) or with `shrink`, the active underline is the title-embedded line whose `left: 50%` pins only the line's left edge without pulling back its own half width, shifting the whole line right by half of `line-width` (20px with the default 40px); the standalone bottom line of the equal-width layout is unaffected. A `transform: translateX(-50%)` centering pullback is added (translateX percentages resolve against the element's own width on every platform and adapt to any `line-width`)
- **m-tabs throws TypeError on mounted on WeChat Mini Program, leaving no active tab on first paint**: on Mini Program the `UniElement` only exposes the async `getBoundingClientRectAsync` and has no synchronous `getBoundingClientRect`, so the component throws `TypeError: el.getBoundingClientRect is not a function` in `measureWidth` right at mounted, and the rest of the same hook (active-state initialization) never runs — first paint shows no active tab and no bottom line. Three fixes: `measureWidth` only measures in the freeLine layout (standalone bottom line) and `swipeable` (track translation / gesture threshold) scenarios (selfWidth is not consumed elsewhere), App / Mini Program go through the async API while Web keeps the synchronous measurement (platform branches aligned with m-sticky); the `scrollspy` scroll-driven activation and click-to-scroll are likewise split per platform (on Mini Program all panes are measured asynchronously in a batch and then judged together). Web behavior unchanged ([#5](https://github.com/MengXi-Studio/unix-ui/issues/5))

## [0.4.0] - 2026-11-11

New m-tabs / m-tab tabs components; m-image adds tap-to-preview.

### Added

- **m-tabs / m-tab tabs**: content switching container with `line` / `card` / `pill` styles; `active` supports mixed index / name matching (exact match by name type first, falls back to index); the tab bar scrolls horizontally beyond `swipe-threshold` and centers the active tab; `animated` track translation transition + `swipeable` follow-finger gesture switching (gesture does not trigger `before-change`, aligned with Vant); `sticky` header reuses m-sticky and `scrollspy` scroll navigation (flat content + scroll-driven activation + click-to-scroll); `before-change` interception (synchronous boolean version); `options` array bar-only form (`field-names` mapping); title badges (dot / badge / show-zero-badge) and nav-left / nav-right slots (see [Tabs](/en/components/tabs))
- **m-image tap-to-preview**: with `preview` enabled, tapping the image calls `uni.previewImage` to open the full-size preview (available on every platform: Web / WeChat / Alipay Mini Programs / Android / iOS / HarmonyOS), responding only in the loaded-success state; `preview-list` specifies the list of URLs to preview (falling back to the single `[src]` when omitted or empty), the start index is resolved to the position of the current `src` in the list (falling back to 0 when not found), and `preview-current` sets it explicitly; enabling `preview` does not swallow the `click` event — both work together (see [Image](/en/components/image))

## [0.3.1] - 2026-11-09

WeChat Mini Program adaptation fixes: m-overlay visibility and transition timing, m-icon font loading.

### Fixed

- **m-overlay overlay visibility broken on Mini Program**: the root `v-show` is compiled by the uni-app x compiler into a `virtualHostHidden` expression that gets short-circuited by the external default `false`, so hidden transparent full-screen overlays stayed on top intercepting every touch and no button on the page was clickable; the root `v-show` is removed and the hidden state now appends `display: none` at the end of rootStyle (placed after custom-style to override its display declaration). The root `v-if` remains unusable (on the uni-app x Web runtime, event bindings passed through attrs are lost when the root node switches from a comment node to a created node), and popup components composed on m-overlay such as m-popup are fixed on Mini Program accordingly
- **m-overlay fade without a gradual appearance on Mini Program**: the Mini Program render layer merges two setData updates that fire too closely into a single paint — the opacity 1 set after nextTick (a logic-layer microtask) gets merged with the display removal into the same paint, so the transition has no starting point and the overlay just pops in; the non-Web show trigger changes from nextTick to a 50ms timeout to stagger the timing (ensuring the first frame after the display:none removal has finished painting; 50ms is imperceptible within a transition starting at 0.3s), while the Web double-rAF timing is unchanged
- **m-icon font loading failure on WeChat Mini Program**: `@font-face` in wxss does not support local font file paths (Web / App are unaffected), so icons all rendered as default glyphs; on MP-WEIXIN the in-style `@font-face` declaration is excluded via conditional compilation and replaced by a runtime `uni.loadFontFace` call in onMounted (`global: true` to apply to all pages) loading a base64 inlined font (new `m-icon-font.uts`, font data bundled in the package with zero configuration); icons may flash with default glyphs on the first frame, which is a known limitation

## [0.3.0] - 2026-11-05

Adds the flex layout components (m-flex / m-flex-item), the status bar placeholder component (m-status-bar), the sticky layout components (m-sticky / m-sticky-box), the waterfall components (m-waterfall / m-waterfall-item / m-waterfall-load) and the cascader family (m-cascader / m-cascader-popup / m-cascader-input, form family).

### Added

- **m-cascader / m-cascader-popup / m-cascader-input cascader family**: modeled after Vant Cascader, split into three components by "panel / popup / input" — m-cascader pure inline panel (header + level tabs + swiper-hosted level option lists, `v-model:value` leaf value of the `string | number` union type, options as the dynamic type `UTSJSONObject[]` supporting `field-names` mapping and async loading (modifying children inside the change callback re-renders automatically; an empty array is treated as a leaf and finishes directly), `swipeable` gesture level switching (hosted by disable-touch), `active-color` theme color derivation, `options-height` options area height (prop overrides the theme variable), closeable / close-icon / show-header header capabilities; change / finish / close / click-tab events and the four slots title / option / options-top / options-bottom, external `value` rebuilds the path from the options tree with a guard against v-model write-back loops); m-cascader-popup popup cascader composed on m-popup (full popup props pass-through, auto close after finish, `v-model:value` controlled value pass-through, conditional forwarding of cascader events and the four slots, header close icon uniformly closes via update:show); m-cascader-input composed of an m-input readonly trigger + popup (`v-model:value` write-back on finish, path text joined with "/" for display (falls back to the value string when the path is not found), self-drawn clear button, disabled / border / inlaid forms, full pass-through of field-names / options-height / swipeable); adds the `$m-cascader-*` and `$m-cascader-input-*` theme variable sections (see [Cascader](/en/components/cascader))
- **m-flex / m-flex-item**: four `direction` values (row / row-reverse / column / column-reverse, equivalent to flex-direction), three built-in `gap` sizes (small / medium / large mapped to `$m-flex-gap-sm` / `$m-flex-gap` / `$m-flex-gap-lg`) plus custom sizes (number gets a px suffix / string used as is), four `align` values (equivalent to align-items; baseline falls back to flex-start on App), six `justify` values (equivalent to justify-content, adding between / around / evenly), a `flex` CSS shorthand pass-through, `wrap` auto wrapping (row / row-reverse only) and a default slot; spacing is implemented via the margins of m-flex-item (flex `gap` is not supported by ucss on App), with items sensing their position through provide/inject + reactive registration order — non-first items in row and non-last items in row-reverse get `margin-left`, non-first items in column get `margin-top`, non-last items in column-reverse get `margin-bottom` (reversed directions leave no extra space at either end); when wrapping horizontally every item gets `margin-left` with an equal negative margin on the container (all lines start flush) and the line spacing is the item's `margin-bottom` (an extra spacing below the last line is a known limitation); unwrapped children do not participate in spacing, and standalone use of m-flex-item degrades to an ordinary vertical container
- **m-status-bar placeholder**: reserves the system status bar height for top-anchored elements such as Navbar / Notify; the `height` prop (px, used directly when greater than 0) takes precedence, otherwise the App platform reads `uni.getWindowInfo().statusBarHeight` automatically while Web / Mini Program stay at 0 (no placeholder); `custom-class` / `custom-style` direct styling (background etc.), no dedicated theme variables; the playground demo-navbar now consumes this component
- **m-sticky (controlled sticking on every platform)**: the page passes `scroll-top` from the scroll container's `@scroll` event, and the component walks up `parentElement` to locate the nearest scroll container (by the `uni-scroll-view` class on Web, by "scroll height greater than visible height" on App / Mini Program) and uses its visible area as the sticking reference; when stuck the content node switches to `position: fixed` while the root keeps the measured placeholder height so the layout does not collapse. **Native CSS `position: sticky` is not used**: the uni-app x Web runtime injects `overflow: hidden` into every `view`, so the nearest scroll container of sticky degenerates into a non-scrolling parent and never sticks (verified: rect.top stays at -198 after scrolling 400px). `position` (top / bottom) with mutually exclusive `offset-top` / `offset-bottom` (relative to the scroll container's visible edge, so a custom navbar needs no extra offset), `z-index` (99 by default via the theme class, overridden inline only when non-default), `custom-class` / `custom-style` (attached to the content node), and `change(isFixed)` / `scroll({ scrollTop, isFixed })` events; measured only on first render and re-measured on window resize, so content size changes require rebuilding the component (no `refresh()`)
- **m-sticky-box container boundary**: provide/inject hands an inner m-sticky the container `UniElement` reference so the sticky element stops at the container's top / bottom edge (replicating Vant's containerVisible check and translateY compensation); the container needs an explicit height to create the sticky travel range; adds the theme variable `$m-sticky-z-index: 99 !default`
- **m-waterfall / m-waterfall-item / m-waterfall-load**: the container measures its available width and divides it into columns; each item measures its own height at the correct width and reports it back, then the container computes absolute positions (left / top / width) with "registration order → shortest column first" and writes back the total height. Layout is strictly sequential (later items stay hidden while an earlier one is still loading, so placed items never jump), and unloaded items reserve their correct column width with `visibility: hidden` so heights are measured accurately. `columns` (2 by default), `column-gap` / `row-gap` (px, 16 by default), `custom-class` / `custom-style`; the item slot exposes `onLoad` (call when content finishes loading to re-measure) and `columnWidth`; `loadstart` / `load` events plus `reflow()` / `onLoad(handler)` instance methods; `m-waterfall-load` reserves height from width / height via `padding-top`, uses the natural image size when loaded within `max-wait`, keeps the custom ratio after a timeout and exposes `overtime`. There is no ResizeObserver (the width is measured on mount / window resize / reflow), and horizontal padding on the container eats into column width (put gutters on an outer wrapper)

### Fixed

- **VDOM Web runtime TS diagnostic WARNING cleanup (32 prop types)**: a nullable prop declared `T | null` with a null default made the compiler emit props as `type: [T, null]` (rejected by Vue's Prop typings), producing `No overload matches this call` noise that also leaks into end users' runtime logs; nullable props now drop the `| null` annotation while **keeping `default: null`** (the runtime value is still null when omitted — three-state semantics and behavior unchanged) — covering `value` / `minDate` / `maxDate` / `defaultDate` / `formatter` / month `panel` on m-calendar, the same set on m-calendar-popup, `value` / `minDate` / `maxDate` on m-calendar-input, `offset` on m-col, `justify` / `align` on m-row, `gutter` / `columnNum` / `iconSize` on m-grid, `icon` / `gutter` on m-grid-item, `width` / `height` / `radius` on m-image, `size` / `align` on m-space, `formatter` / `precision` / `min` / `max` on m-input, `icon` / `clickable` on m-cell, `type` / `position` / `icon` / `forbidClick` / `loadingType` / `duration` / `wordBreak` on m-toast, and `beforeClose` on m-popup; the remaining 3 SSRSlot WARNINGs come from the generated code of conditional slot forwarding and are compiler typing noise with no runtime impact

## [0.2.0] - 2026-11-03

Adds the popup-family base components (m-overlay / m-popup), the divider component (m-divider), the grid components (m-grid / m-grid-item), the toast component (m-toast, feedback family), the compact layout component (m-compact, layout family), the input component (m-input, form family) and the calendar component family (m-calendar / m-calendar-popup / m-calendar-input, form family), bringing the total to 18 base components.

### Added

- **m-overlay**: `show` visibility, `z-index` level, `duration` in seconds (`0` disables animation), `custom-class` / `custom-style` direct styling and a `click` event (the overlay does not close automatically, aligned with Vant semantics); built-in body scroll lock on Web (released only when all stacked instances close), the foundation of popup components
- **m-popup**: five positions (center / top / bottom / left / right), per-side round corners, closeable with `close-icon` / `close-icon-position`, `close-on-click-overlay`, overlay customization (`overlay` / `overlay-class` / `overlay-style`), `z-index` / `duration`, `lazy-render` / `destroy-on-close`, `safe-area-inset-top` / `safe-area-inset-bottom`, and a `before-close` guard (sync boolean); `v-model:show` two-way binding with full events (open / opened / close / closed / click / click-overlay / click-close-icon); center scales in with a fade, edge positions slide, composed on top of m-overlay
- **m-divider**: horizontal / vertical forms (vertical as a flex item; parent container needs `flex-direction: row` + `align-items: center`), `dashed`, `hairline` 0.5px thin line (1px border + single-axis 0.5 scale, safe on App platforms), `content-position` (left / right / center, one line width-capped at 10%), default slot with inherited text styles
- **m-grid / m-grid-item**: `column-num` custom columns, `square` cells (percentage padding-top + absolutely positioned content), `gutter` spacing (same value for rows / columns, evenly distributed per the m-row precedent), `border` full table borders (container draws the top + left lines, items draw the right + bottom lines), `center` content centering, `direction` horizontal layout, `reverse` icon-text swap, `clickable` press feedback (native view hover-class); per-item `text` / `icon` / `icon-color`, `dot` / `badge` (via m-badge), `click` events and `url` in-app page navigation, with default / icon / text slots
- **m-toast**: imperative API (`showToast` / `showSuccessToast` / `showFailToast` / `showLoadingToast` / `closeToast`, string shorthand or ToastOptions object, singleton semantics) and component usage (`v-model:show` + default slot); `type` (text / loading / success / fail), `position` (top / middle / bottom), custom `icon`, `overlay` / `forbidClick` masking and click interception, `closeOnClick` / `closeOnClickOverlay`, `duration` (loading defaults to 0, no auto close), `wordBreak` wrapping control (normal / break-all on all platforms; break-word is Web / Mini Program only, App falls back to normal, aligned with Vant), `onOpened` / `onClose` callbacks and opened / close events; built on the "global functions + page-level container + global singleton bridge" approach (uni-app x has no runtime dynamic mounting), keeping the API feel aligned with Vant
- **m-compact**: wraps m-button so adjacent items join their corner radii and merge neighboring borders into 1px, with variant mixing supported; `block` fills the parent width (horizontal `flex: 1` even split / vertical full width, no need to set block per button), `direction` horizontal / vertical; first / middle / last positions recalculated automatically when children are added or removed via `v-if` / `v-for`; the 0.5px hairline scale layer clears the corresponding side radii and borders in sync; position sensing is built on provide/inject + reactive registration order (ucss has no `:first-child` structural selectors), no dedicated theme variables (radii / borders reuse the `$m-button-*` family, see [Compact](/en/components/compact))
- **m-space-item**: the wrapper component for m-space children; spacing is implemented via its margins — flex `gap` is not supported by ucss on App, where the gap declaration was silently dropped by the compiler, breaking spacing; each item senses its position via provide/inject + reactive registration order (reusing the m-compact precedent); in the horizontal direction every item gets margin-left with an equal negative margin on the container (all wrapped lines start flush), in the vertical direction non-first items get margin-top, and in wrap scenarios the line spacing is the item's margin-bottom (an extra spacing at the bottom of the last line is a known limitation); unwrapped children do not participate in spacing, and standalone use degrades to an ordinary vertical container (see [Space](/en/components/space))
- **m-input**: six types (text / tel / digit / number / password / textarea), `clearable` + `clear-trigger` dual timing (focus / always, aligned with Vant), `maxlength` (-1 for unlimited) + `show-word-limit` character counting, `border` / `inlaid` (strips border and padding for cell embedding), `disabled` / `readonly` (readonly simulated via disabled, no native support), `confirm-type`, textarea `auto-height`; `formatter` + `format-trigger` (onChange / onBlur), `precision` with trailing zeros kept, `min` / `max` blur-time numeric clamping, `show-eye` plaintext toggle (aligned with Sard); prepend / append slots, `v-model` unified as string with input / change (blur-time snapshot comparison mimicking Vant semantics) / focus / blur / clear events, exposed `focus()` / `blur()` methods; injects the m-compact context to mix with m-button (see [Input](/en/components/input))
- **m-calendar / m-calendar-popup / m-calendar-input**: aligned with Vant Calendar, split into three components by "panel / popup / input" — m-calendar is a pure inline panel (three selection types single / multiple / range, `switch-mode` year-month navigation clamped to the selectable range, `formatter` day customization, `first-day-of-week`, `row-height`, month watermark, `height` panel height, `color` theme color deriving the selected dot and range bar (gradients supported), `min-date` / `max-date` out-of-range disabling, `max-range` over-range limit shared by range and multiple (rejected + `over-range` + m-toast prompt), `allow-same-day`, `default-date` pre-selection; select / confirm / unselect / over-range / month-show / panel-change / click-subtitle / click-disabled-date events with 12 slots; exposed `reset()` / `resetSelection()` / `scrollToDate()` / `getSelectedDate()` / `refreshView()` methods); m-calendar-popup is a popup calendar composed on m-popup (popup props fully forwarded plus `popup-height` percentage conversion, auto-close on confirm, `refreshView` resetting the focused month on reopen, `v-model:value` controlled selected value forwarding, `reset-on-open` resetting the selection to value / default-date on open, calendar events and slots conditionally forwarded); m-calendar-input is composed of an m-input read-only trigger plus the popup (`v-model:value` write-back on confirm, single value / range span / multiple joined text display, self-drawn clear button, disabled / border / inlaid trigger forms, inner selection resetting to the current value on popup open (`reset-on-open` enabled internally)) (see [Calendar](/en/components/calendar))

### Fixed

- **Dual-mode (Vapor / VDOM) cloud packaging compatibility**: fixed all Kotlin errors from the VDOM compilation output, so the library packages under either mode (Web behavior unchanged) — explicit return types on 10 `watch` sources, slot detection via index access `slots['default']` (6 components), m-loading `Animation` → `UniAnimation`, local bridging of calendar.uts helpers called from m-calendar-panel templates, and m-calendar-popup event handlers unified as const arrow functions with `$slots['xxx']` index access
- **ucss compile ERROR cleanup (App)**: m-divider content-position line `max-width: 10%` replaced with `flex: none` + `width` (percentage max-width unsupported on App); m-toast bubble width cap injected at runtime as px (window width × 70%) on App (also fixes the dropped declaration leaving long text uncapped); `word-break: break-word` excluded on App via conditional compilation, falling back to normal; m-space spacing refactored to the m-space-item margin approach (flex `gap` unsupported by ucss on App, where the declaration was silently dropped, breaking spacing), all gap usages removed from demo pages in sync, gap WARNINGs cleared in dual-mode cloud packaging
- **Android cloud packaging Kotlin errors**: 4 use-before-declaration issues (m-calendar watch callback / m-input event bridges / m-toast close flow / demo page helper declaration order) and 3 typing issues (explicit `as string` for `custom-class`, null short-circuit in `hexDigitValue`, explicit type for the first m-row group)

## [0.1.0] - 2026-10-27

First usable release: a UI component library for uni-app x with a pnpm monorepo architecture (core / docs / playground), one set of UTS + uvue sources covering multiple platforms, with 9 built-in base components.

### Added

- **m-button**: five types (default / primary / success / warning / danger), four sizes (large / normal / small / mini), plain, round, square, block, disabled, loading state (loading / loading-text, the loading icon is powered by [m-loading](/en/components/loading), `loading-type` supports `circular` / `spinner`), press feedback (hover-class based, opacity overridable via `$m-button-active-opacity`), custom color (color, supporting `linear-gradient` gradients) and hairline borders
- **m-badge**: badge number / text / dot at the top-right corner, max truncation (`{max}+`), semantic color names and CSS color values, four-corner position, offset-x / offset-y, show-zero and a content slot for custom content; displays standalone without a child element, combinable with m-icon
- **m-icon**: 257 built-in font icons (`name` is the `IconName` union type), `color` / `size` customization, `custom-class` / `custom-style` direct tag styling, an `icon` slot and `click` events; the font file ships with the package (`@font-face` declarative loading), zero configuration, offline available
- **m-loading**: two loading types (circular arc ring / spinner petals), custom color (`color`, CSS color values or semantic color names), custom size (`size`, supports `100%` to fill an externally sized container), vertical layout (`vertical`), custom text styling (`text-size` / `text-color`), default text slot and custom icon slot; the spinner type uses 1.2s 12-step discrete rotation with a fading tail, the circular type is an arc ring rotating at a constant speed, animations are powered by `UniElement.animate` (ucss has no `@keyframes`)
- **m-cell / m-cell-group**: title / value / label, icons, four-direction arrows, inset rounded-card groups
- **m-row / m-col**: grid layout with gutter spacing, alignment and wrapping
- **m-image**: mode passthrough, loading / failure placeholders, fade-in transition, circle, lazy loading
- **m-text**: semantic color / color value dual mode, three font sizes, single-line ellipsis, multi-line truncation, selectable
- **m-space**: direction / wrap / alignment, size as a single value or dual values (row / column)
- **easycom auto import**: uni_modules-compliant directory layout (`uni_modules/m-ui-x/components/<name>/<name>.uvue`), no import or registration needed; an `easycom.custom` rule in pages.json for npm installs
- **Theming**: the default theme is built in and requires zero configuration (components import `theme/vars.scss` at the top level, all `!default`); define `$m-*` variables in the project root uni.scss to override globally at compile time — see [Theming](/en/guide/theming)
- **0.5px hairline borders**: ucss has no pseudo-elements, implemented with an absolutely positioned view + `scale(0.5)`, consistent across Web and native
- **Event semantics**: click does not fire while disabled or loading

### Engineering

- **pnpm monorepo**: packages/core (component source) / packages/docs (VitePress site) / packages/playground (uni-app x demo project)
- **uni_modules sync script**: `sync-uni-modules.mjs` syncs core into playground `uni_modules/m-ui-x` with a sha256 consistency check (`--check`)
- **Vapor mode**: playground enables `vapor: true` + `vapor-render-target: bytecode`; components verified under vapor compilation
- **VitePress docs site**: local search (Chinese translations), UTS syntax highlighting, dark code theme, home badges

### Platform Support

- **Web**: compile and runtime verified (rendering, events and theme override matrix tested)
- **Android / iOS / HarmonyOS / Mini Programs**: adapted via conditional compilation, pending on-device testing
