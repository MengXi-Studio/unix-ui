# @meng-xi/unix-ui v0.2.0 发布：18 个基础组件 + 真机演示 App，弹窗 / 表单 / 日历全家桶到位

> v0.2.0 新增 **10 个组件**：弹窗基座 m-overlay / m-popup、分割线 m-divider、宫格 m-grid、轻提示 m-toast、紧凑布局 m-compact、输入框 m-input、日历三件套 m-calendar / m-calendar-popup / m-calendar-input。蒸汽与非蒸汽双模式云打包验证通过，并放出 **Android 真机演示 App**（APK 直装）。本文带代码，一次讲清用法与背后的工程决策。

## 一、从 11 到 18：这次补齐的是「业务拼图」

v0.1.0 交付的是骨架：按钮、文本、图标、栅格——撑得起界面，撑不起业务。真实业务页面永远缺三样东西：**弹层**（提示、确认、抽屉）、**表单**（输入、选择、日期）、**反馈**（成功 / 失败 / 加载中）。

v0.2.0 一次补齐，全部组件遵循同一套契约：easycom 免注册、`$m-*` SCSS 变量编译期主题定制、UTS 源码分发多端编译。组件划分、props 命名与主流 uni-app 组件库对齐，心智零迁移。

## 二、新组件逐个讲（带代码）

### 弹窗基座：m-overlay + m-popup

所有弹层类组件的地基。m-overlay 是全屏遮罩层——淡入淡出过渡、层级控制、Web 端自动滚动锁定；m-popup 在此之上提供五种方位的弹出容器：

```html
<template>
	<!-- 底部弹出面板：圆角 + 关闭图标，关闭时销毁内容 -->
	<m-popup v-model:show="show" position="bottom" round :close-on-click-overlay="true">
		<view class="panel">
			<text>底部抽屉内容</text>
		</view>
	</m-popup>
</template>
```

关键实现细节：过渡动画走 `UniElement.animate`（ucss 禁用 `@keyframes`），`destroy-on-close` 控制内容销毁重建，弹出完成后才派发 `opened` 事件——动画时序是确定性的，不依赖各端 CSS transition 事件的实现差异。

### 函数式轻提示：m-toast

轻提示是使用频率最高的反馈组件，v0.2.0 把它做成了「两种姿势」：

```typescript
// 函数式：页面任意位置直接调用
showToast('提示内容')
showSuccessToast('保存成功')
showLoadingToast('加载中...')   // duration 0 不自动关 + 禁止点击
closeToast()                    // 业务完成后手动关闭

// 对象式：覆盖默认行为
showToast({
	message: '顶部提示',
	position: 'top',
	duration: 1500,
	overlay: true,                // 半透明遮罩
	onOpened: () => { /* 淡入完成 */ },
	onClose: () => { /* 已关闭 */ }
})
```

组件式 `<m-toast v-model:show="show">` 则在 default 插槽里嵌任意内容（图片 + 文案的富气泡、表单确认气泡），两种用法共享同一过渡与层级机制。`word-break` 换行策略做了全端适配：normal / break-all 全端生效，break-word 在 App 端自动回退 normal（ucss 只认前两种）。

### 表单组合：m-input + 日历三件套

**m-input** 六种类型（text / number / digit / idcard / textarea / password），工程化细节拉满：

- 内置清除图标、密码明文切换
- `formatter` 格式化 + 数字精度收敛（金额、小数位场景不用自己写截断）
- 字数统计、textarea 多行自适应
- 前置 / 后置插槽（金额符号、发送验证码按钮）

**日历三件套**是一组递进组合——面板、弹层、表单控件各司其职：

```html
<!-- 面板：单选 / 多选 / 范围，formatter 定制日期角标 -->
<m-calendar v-model:show="show" type="range" @confirm="onConfirm" />

<!-- 弹层组合：底部弹出 + 确认自动关闭 -->
<m-calendar-popup v-model:show="show" type="single" @confirm="onPick" />

<!-- 表单组合：input 载体，点击选择、格式化回填、支持清空与禁用 -->
<m-calendar-input v-model="date" type="single" placeholder="请选择日期" />
```

业务页面里最常用的是第三个：一行标签即得完整日期选择控件，不用自己组装 input + 弹层 + 回填逻辑。

### 布局补强：m-grid + m-compact + m-space-item

- **m-grid**：自定义列数、正方形格子、间距、横排反向、徽标、点击跳转——九宫格菜单的标准解法
- **m-compact**：让一组按钮紧凑连接，相邻边框自动合并为 1px（普通按钮 1px + hairline 0.5px 缩放层混排也能正确衔接），`block` 模式水平 `flex: 1` 等分。子项 `v-if` / `v-for` 动态增删时首、中、尾位置自动重排——这是靠 provide/inject + 注册序实现的，uvue 没有 `$children`，ucss 没有 `:first-child`，父组件「看不见」子组件，只能让子组件自己报数
- **m-space-item**：间距子项，见下一节，它是本期最有故事的一个组件

## 三、硬核细节：App 端没有 flex gap 怎么办

一个看似简单的能力——「子元素之间留 8px 间距」——在 uni-app x 的 App 端是个坑。

**结论先行：App 端 ucss 不支持 flex `gap` / `row-gap` / `column-gap`。** 声明写上去不报错、不拦截，编译器只给一条「gap is not a standard property name」的 WARNING，然后**静默丢弃**——Web 端间距正常，App 端间距消失，极易漏测。

我们没有停在「WARNING 不阻断编译」的表象上，而是做了三段证据链实证：

1. **编译器 lint 层**：读 HBuilderX 插件源码 `uni-nvue-styler.cjs.js`，属性表外属性仅告警且保留值——「保留」不等于「生效」；
2. **官方文档**：uni-app x 的 CSS 属性清单有 `lines`、无 `gap`（同一条 WARNING 里的 `lines` 是官方属性，纯属 lint 噪音，可放心用）；
3. **原生运行时**：解包 Android 运行时 jar，`UniCSSPropertyID.class` 常量池里有 `flex-direction`、有 `lines`，没有任何 gap 系列——原生层根本不认识这个属性。

三段对齐后定案：gap 必须绕开。但替代方案不平凡——

- 间距类加在「非首项」上？ucss 没有 `:first-child`，且 flex-wrap 换行后**每行行首项**在注册序里仍是非首项，会带出 8px 缩进，换行布局「参差不齐」；
- 插槽直通的容器给任意子元素加 margin？uvue 没有 `$children`，做不到。

最终方案是 **m-space-item 包裹重构**（v0.2.0 的 API 变化点）：每个子项显式包裹 `<m-space-item>`，子组件在 setup 中同步注册自身 id（provide/inject + reactive 注册序），按位次注入 margin；容器再施加**等值负 margin-left 补偿**（经典 gutter 技法），换行各行行首与首行顶格。浏览器实测：4 行换行行首 x 坐标完全相等，间距精确 8px。

```html
<!-- v0.1.0 写法 -->
<m-space><m-button>按钮</m-button></m-space>

<!-- v0.2.0 写法：子项包裹 -->
<m-space>
	<m-space-item><m-button>按钮</m-button></m-space-item>
	<m-space-item><m-button>按钮</m-button></m-space-item>
</m-space>
```

同类的平台差异适配本期还有两处：m-divider 的 `max-width: 10%` 改 `flex: none` + 定宽（App 端 max-width 不支持百分比）；m-toast 气泡宽度上限在 App 端改运行时按窗口宽 70% 换算 px 注入。每一条都写进了项目的经验教训库——「编译期不报错」和「运行期正确」之间，隔着整个端差异矩阵。

## 四、主题定制：一行变量全局生效

新组件全部接入 `$m-<组件>-<属性>` 命名契约（全 `!default`），在工程根 `uni.scss` 直接定义同名变量即可覆盖，编译期注入、零运行时开销：

```scss
/* 弹窗圆角 24px → 16px */
$m-popup-radius: 16px;
/* 日历选中日底色 → 主题绿 */
$m-calendar-selected-background-color: #07c160;
```

组件内顶层无条件引入 `vars.scss`，用户零配置即有默认主题；覆盖变量按 `$m-<组件>-<属性>` 命名对账，全部可用变量见包内 `theme/vars.scss`。

唯一红线（v0.1.0 已提过，升级用户重点看）：**不要在 `uni.scss` 里 `@import` 包内 `vars.scss`**——`uni.scss` 注入每个组件样式，与组件内引用同一文件会触发 sass 循环导入。
