# @meng-xi/unix-ui v0.3.0 发布：瀑布流 / 粘性布局 / 级联选择三件套上线，一次讲清 uni-app x 的三个「不能」怎么绕

> v0.3.0 新增 **11 个组件**：弹性布局 m-flex / m-flex-item、状态栏占位 m-status-bar、粘性布局 m-sticky / m-sticky-box、瀑布流 m-waterfall / m-waterfall-item / m-waterfall-load、级联选择三件套 m-cascader / m-cascader-popup / m-cascader-input。VDOM 模式云打包验证通过，Android 真机演示 App 已同步重打。本文带代码，重点讲清三个「平台不支持」背后的实现决策。

## 一、这个版本补的是「复杂布局」与「级联选择」

v0.2.0 交付后，组件库在基础控件层已经齐整。但真实业务页面还有两类高频刚需：

**复杂布局**——瀑布流商品流、吸顶筛选栏、弹性按钮组、沉浸式头部。这四件事在 Web 前端是成熟能力，在 uni-app x 里各自藏着一个「平台不支持」：不支持 ResizeObserver、原生 `position: sticky` 失效、App 端没有 flex `gap`、状态栏高度读不到。

**级联选择**——省市区、品类规格，表单里最复杂的输入控件。我们按「面板 / 弹出框 / 输入框」拆成三个组件，与日历三件套同一套拆分哲学：每一层都能单独使用，组合起来零成本。

当前组件全景（按文档站五组分类）：

| 分组 | 组件 |
| --- | --- |
| 基础 | m-button、m-icon、m-image、m-text |
| 表单 | m-input、m-calendar 三件套、m-cascader 三件套 |
| 反馈 | m-toast、m-loading、m-overlay、m-popup |
| 布局 | m-row / m-col、m-grid、m-space、m-compact、m-divider、m-flex、m-status-bar、m-sticky |
| 数据展示 | m-badge、m-cell / m-cell-group、m-waterfall |

## 二、新组件逐个讲（带代码）

### 瀑布流：m-waterfall / m-waterfall-item / m-waterfall-load

三件套各司其职：容器测宽分列、项上报真实高度、加载器按已知宽高占位——

```html
<m-waterfall :columns="2" :column-gap="16" :row-gap="16" ref="wf">
	<m-waterfall-item v-for="item in list" :key="item.id" #default="{ onLoad }">
		<!-- 已知宽高：max-wait 内加载完成取图片真实比例，超时保留自定义比例 -->
		<m-waterfall-load :width="200" :height="150" #default="{ overtime }">
			<image :src="item.url" @load="onLoad" />
			<text v-if="overtime">加载超时</text>
		</m-waterfall-load>
	</m-waterfall-item>
</m-waterfall>
```

动态增删后调 `reflow()` 重新排版；`loadstart` / `load` 事件可用于首屏 loading。实现细节见第三节。

### 粘性布局：m-sticky / m-sticky-box

页面滚动容器把 `@scroll` 的 `scroll-top` 回传给组件，其余交给组件——

```html
<scroll-view :scroll-y="true" @scroll="onScroll">
	<m-sticky :scroll-top="scrollTop" :offset-top="44" @change="onStickyChange">
		<view class="filter-bar">吸顶筛选栏</view>
	</m-sticky>
	<!-- 页面内容 -->
</scroll-view>
```

`position`（top / bottom）、互斥的 `offset-top` / `offset-bottom`（相对滚动容器可视边缘，自定义导航栏无需叠加高度）、`change(isFixed)` 与 `scroll({ scrollTop, isFixed })` 事件一应俱全。包一层 `m-sticky-box` 可把吸附范围限制在容器边界内（到边自动回顶，复刻 Vant 容器语义）。

### 弹性布局：m-flex / m-flex-item

一个组件等价于对 flex 容器配置 `flex-direction` / `align-items` / `justify-content` / `flex-wrap` / `flex` 全套属性，间距三档内置（small / medium / large）或自定义尺寸——

```html
<m-flex direction="row" gap="medium" justify="between" align="center">
	<m-flex-item><m-button>取消</m-button></m-flex-item>
	<m-flex-item><m-button type="primary">确定</m-button></m-flex-item>
</m-flex>
```

子项间距由 m-flex-item 按「注册序轮位」注入 margin 实现——因为 App 端 ucss 不支持 flex `gap`（v0.2.0 文章的三段证据链结论），这是我们在组件库层面的最终解法，业务代码从此不用感知这个坑。

### 状态栏占位：m-status-bar

```html
<!-- 沉浸式头部：状态栏高度自动占位 -->
<view class="navbar">
	<m-status-bar />
	<text>标题</text>
</view>

<!-- 也可以显式指定高度 -->
<m-status-bar :height="44" />
```

App 端自动读取系统状态栏高度，Web / 小程序端保持 0 不占位。一行代码解决沉浸式头部的顶格问题。

### 级联选择三件套：m-cascader / m-cascader-popup / m-cascader-input

与日历三件套完全同构的拆分：面板、弹层、表单控件递进组合——

```html
<!-- 纯面板：嵌入页面直接选 -->
<m-cascader v-model:value="area" :options="regionOptions" @finish="onFinish" />

<!-- 弹层：底部弹出，选完自动关闭 -->
<m-cascader-popup v-model:show="show" :options="regionOptions" @finish="onPick" />

<!-- 表单：一行得到完整选择控件 -->
<m-cascader-input v-model:value="area" :options="regionOptions" placeholder="请选择地区" />
```

面板层的能力对齐 Vant Cascader：`field-names` 字段名映射、异步加载（change 回调内填充 children 自动渲染，空数组视为叶子直接 finish）、`swipeable` 手势换层、`active-color` 主题色派生、title / option / options-top / options-bottom 四插槽；`v-model:value` 受控叶子值，外部回灌自动按选项树重建路径。

## 三、硬核细节：三个「平台不支持」的实现决策

### 1. m-sticky 为什么不用原生 position: sticky

我们最早就是用 CSS `position: sticky` 实现的——然后在 Web 端实测发现**完全不吸附**：滚动 400px 后吸附元素 rect.top = -198，纹丝不动地跟着滚走了。

排查结论：uni-app x 的 Web 运行时给所有 `view` 注入 `overflow: hidden`。CSS sticky 的吸附基准是「最近的滚动祖先」，而 overflow: hidden 的父级在规范里也算一种滚动容器——sticky 元素的基准被它截胡，退化成一个不会滚动的父级，吸附行程归零。

解法是**全端受控吸附**：页面把 scroll-top 回传给组件，组件沿 parentElement 自动识别真实滚动容器，吸附时把内容节点切 `position: fixed`、根节点回填实测占位高度避免布局塌陷。代价是不支持内容动态变高（需重建组件），换来全端一致的确定性吸附。

### 2. 瀑布流没有 ResizeObserver 怎么保证「不跳动」

uni-app x 没有 ResizeObserver，容器宽度变化只能靠挂载 / 窗口 resize / 手动 `reflow()` 三时机测量。真正难的是排版稳定性，我们定了两条铁律：

- **最短列优先 + 严格顺序**：前一项未上报高度时，后续项即使已知高度也隐藏等待——牺牲首屏并发，换「任何时刻已显示的项位置永不变」；
- **占位即测量**：未加载项以 `visibility: hidden` 按正确列宽占位（m-waterfall-load 按 width / height 用 padding-top 预占高度），保证后续项测量时列宽已经确定，不会因图片加载完成而整列位移。

### 3. VDOM 云打包的 Kotlin 编译五类坑（发版验证实录）

v0.3.0 云打包验证时，非蒸汽模式 kotlinc 一次报了 **17 条错误**——而本地编译、Web 构建、蒸汽模式全部通过。根因在于 .kt 由本地生成、kotlinc 只在云端跑，中间隔着 uni-app x 的 VDOM 代码生成器。逐条归因后收敛为五类，全部从源码层修复：

| 坑 | 正确写法 |
| --- | --- |
| 作用域插槽**重命名解构不绑定**：`{ onLoad: onImageLoad }` 在生成的 Kotlin 里不产出对应变量 | 只用同名解构，嵌套同名靠作用域遮蔽 |
| `watch` 源与回调**缺显式类型**：生成代码推断出 Unit 与实际返回类型冲突 | `watch((): T \| null => props.value, (nv: T \| null) => {...})` |
| 插槽桥接函数参数声明 `any`：插槽实参生成的 Kotlin 是 `Any?`，非空参数类型不匹配 | 桥接参数一律 `any \| null` + 判空 + 显式强转 |
| UTS 的 `is` 类型判断：uvue 编译链直接报语法错误（vue/compiler-sfc 不认） | 收窄 API 或换设计（超时兜底） |
| 仅 Web 支持的 extapi（如 `uni.onWindowResize`）：本地能生成 import，云端 runtime SDK 没有该类，kotlinc 报 Unresolved | 条件编译 `#ifdef WEB` 隔离，查官方兼容性表再落码 |

这套「本地 appResource 导出 + grep 生成 .kt 核对」的回归链路已固化进工程经验库，后续组件从源码层规避。

## 四、主题定制

新组件延续 `$m-<组件>-<属性>` 命名契约（全 `!default`），在工程根 `uni.scss` 直接定义同名变量即可覆盖：

```scss
/* 瀑布流列间距 → 20px */
$m-waterfall-column-gap: 20px;
/* 粘性吸附层级 → 88 */
$m-sticky-z-index: 88;
/* 级联选中项主题色 → 品牌绿 */
$m-cascader-active-color: #07c160;
```

全部可用变量见包内 `theme/vars.scss`。老规矩：不要在 `uni.scss` 里 `@import` 包内 `vars.scss`（sass 循环导入，v0.1.0 已详述）。
