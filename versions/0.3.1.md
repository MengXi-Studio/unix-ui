# @meng-xi/unix-ui v0.3.1 发布：微信小程序适配修复批次——三个「编译器不告诉你」的坑

> v0.3.1 是一个纯修复版本，聚焦微信小程序端：m-overlay 显隐失效导致页面全部按钮点不动、m-overlay 淡入淡出没有渐现过程、m-icon 图标全部显示为默认字形。三个问题的共同点是——本地编译、Web 端、App 端全部正常，只有小程序端出问题，且编译器不报任何错。本文带代码与排查过程，把这三个坑讲透。

## 一、为什么单独发一个修复版本

v0.3.0 发布后，我们把演示工程接入了微信开发者工具实测（appid 已补填配置）。一跑就发现三处「只有小程序端才有」的问题，其中 m-overlay 的显隐失效是致命的——**整个页面被一层看不见的遮罩盖住，所有按钮都无法点击**。

三个问题都已在源码层修复，基于 m-overlay 组合的弹层组件（m-popup / m-cascader-popup / m-calendar-popup）在小程序端同步修复。

## 二、三个坑逐个讲（带排查过程）

### 坑 1：根节点 v-show 在小程序端被短路

**现象**：overlay 演示页在小程序中，页面所有按钮无法点击；元素审查发现多个透明全屏 view 常驻顶层拦截触摸。

**排查**：m-overlay 的显隐用的是根节点 `v-show`，Web 端一切正常。查 uni-app x 编译产物发现，根节点 `v-show` 在小程序端被编译为 `virtualHostHidden` 表达式——而该表达式被外部默认值 false 短路，`display: none` 永远不会生效。编译器对此**静默处理，不报任何错**。

**修复**：移除根节点 `v-show`，隐藏态改为在 rootStyle 末尾追加 `display: none`（置于 custom-style 之后，压制用户传入的 display 声明）——

```ts
const rootStyle = computed<string>(() => {
	let style = 'opacity: ' + opacity.value.toString() + ';'
	// ... z-index / duration / custom-style
	if (!visible.value) style += ' display: none;'
	return style
})
```

顺带说明为什么不用根节点 `v-if`：uni-app x Web 端根节点从注释节点切换创建后，attrs 透传的事件绑定会丢失，点击事件永不触发（v0.2.0 已踩过）。弹窗类组件的根节点显隐，最终只剩 inline style 这一条安全路径。

### 坑 2：淡入淡出没有「渐现」，直接出现

**现象**：修完坑 1 后遮罩能正常显隐了，但淡入动画没有渐现过程——直接跳到最终态。

**排查**：显示流程是「移除 display: none → opacity 从 0 过渡到 1」。原实现在非 Web 端用 `nextTick` 错开两步，Web 端用双 rAF。但小程序渲染层会把**间隔过近的两次 setData 合帧渲染**：nextTick 是逻辑层微任务，之后设置的 opacity 1 与 display 移除合并成同一次绘制，过渡没有起点，直接出现。

**修复**：非 Web 分支改用 50ms 定时，确保 display:none 移除的首帧已绘制完成再置 opacity 1（50ms 在 0.3s 起步的过渡中不可感知）——

```ts
// #ifndef WEB
setTimeout(() => {
	opacity.value = 1
}, 50)
// #endif
```

Web 端双 rAF 时序不变（rAF 与渲染帧对齐，逻辑层定时器在小程序里做不到）。

### 坑 3：wxss 的 @font-face 不支持本地字体路径

**现象**：m-icon 在小程序端全部显示为默认字形（豆腐块），字体根本没加载上。

**排查**：m-icon 的字体声明是 style 内 `@font-face` + 本地 ttf 路径（`/uni_modules/m-ui-x/static/m-icon.ttf`），Web 与 App 端都支持。但 wxss 的 `@font-face` **不支持本地字体文件路径**，这条声明在小程序端被静默丢弃。

**修复**：MP-WEIXIN 端条件编译排除 style 内声明，改为运行时 `uni.loadFontFace` 加载 base64 内联字体——

```ts
// #ifdef MP-WEIXIN
onMounted(() => {
	uni.loadFontFace({
		global: true,
		family: 'm-icon',
		source: M_ICON_FONT_BASE64
	})
})
// #endif
```

`global: true` 使 family 对全部页面与自定义组件生效；字体数据随包内置（新增 `m-icon-font.uts`），依旧零配置、离线可用。已知限制：首帧图标可能先以默认字形闪现，属运行时加载的固有延迟，可接受。

## 三、三个坑的共同规律

把这次的三条经验并排看，规律很清晰：

| 坑 | 平台差异 | 编译器表现 |
| --- | --- | --- |
| v-show 短路 | 根节点 v-show 编译为 virtualHostHidden | 静默，不报错 |
| setData 合帧 | 渲染层合并间隔过近的两次更新 | 逻辑层无法感知 |
| @font-face 本地路径 | wxss 不支持 | 声明被静默丢弃 |

**「本地编译通过 + Web 端正常」不代表全端可用**。小程序端的静默降级（编译产物不符合预期、样式声明被丢弃、渲染层合帧）都不会在任何日志里留下痕迹，只有真机 / 开发者工具实测能暴露。这也是我们把小程序实测纳入发版流程的原因——v0.1.0 文章里「待真机实测」的欠账，本版本开始偿还。
