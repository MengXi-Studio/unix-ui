# @meng-xi/unix-ui v0.4.0 发布：m-tabs / m-tab 标签页组件——uni-app x 里手搓一个对标 Vant 的 Tabs

> v0.4.0 是一个功能版本：新增 `m-tabs` / `m-tab` 标签页组件（line / card / pill 三种风格，全量对标 Vant Tab 的 sticky / scrollspy / animated / swipeable / before-change），并给 `m-image` 补上点击预览能力。Tabs 是目前库内交互最重的组件——本文重点讲三处 uni-app x 约束下的架构取舍：标题栏为什么由容器按快照渲染、animated / swipeable 为什么放弃 swiper 自行编排轨道、scrollspy 的滚动定位为什么要做双路径。

## 一、组件形态：双用法，子组件优先

对标 Vant（交互与 API 主参考）与 Sard Tabs（形态参考），组件拆为 `m-tabs`（容器：标签栏 + 内容区）与 `m-tab`（单个标签页）：

```html
<!-- 子组件式：m-tab 带内容区，主形态 -->
<m-tabs v-model:active="active">
	<m-tab title="标签 1">内容 1</m-tab>
	<m-tab title="标签 2" name="b">内容 2</m-tab>
</m-tabs>

<!-- options 数组式：纯标签栏，无内容区 -->
<m-tabs :options="[{ label: 'A', value: 1 }, { label: 'B', value: 2 }]" />
```

`active` 支持索引与 name 混用匹配：先按 name 的类型（string / number）全等匹配，无命中回退索引 clamp——比 Vant「指定 name 后无法再按索引匹配」宽松，写起来不用纠结 type。`field-names` 支持自定义 options 字段映射。

## 二、uni-app x 约束下的三个架构决策

### 决策 1：标题栏由容器按注册快照渲染

Vant 的 `title` 插槽、`title-style` / `title-class` 在 uni-app x 里做不了：**没有 VNode 移动能力**，m-tab 内部渲染的标题无法上提到容器的标签栏里（uvue 编译为多端，运行时不存在「把子组件渲染结果搬走」的操作）。因此标题栏由容器按 m-tab 的注册快照（title / disabled / dot / badge 等）渲染，`title` 插槽在首版裁剪——文档已注明这一差异。子项注册沿用 provide/inject + reactive 注册序（m-compact / m-flex 先例）。

### 决策 2：animated / swipeable 放弃 swiper，自行编排轨道

动画与手势的最顺手方案是把 m-tab 内容放进 swiper-item，但 uni-app x 无法把自定义组件塞进 swiper-item。最终自行编排：

- **animated**：切换时轨道进入过渡态，`renderSet` 并排 [旧, 新] 两个可见项，`UniElement.animate` 平移轨道到目标位，`setTimeout` 后收缩回单可见项归零位（ucss 无 @keyframes，动画只能走 `UniElement.animate`，watch 启动动画需 `{ flush: 'post' }`）
- **swipeable**：viewport 层挂 touchstart / touchmove / touchend 三事件，跟手位移 + 松手判定阈值切换；手势切换不触发 `before-change`（对齐 Vant）

### 决策 3：scrollspy 滚动定位做双路径

scrollspy 模式下内容平铺，滚动联动激活（基准线为视口固定线 `offset-top`），点击标签反向定位到对应区块。定位采用双路径：

```ts
// 优先向上查找首个可滚容器（scroll-view 内嵌场景），直接平移
const holder = findScrollParent(rootRef.value)   // scrollHeight > offsetHeight + 4 判定
if (holder != null) {
	holder.scrollTop = holder.scrollTop + scrollBy
} else {
	// 页面级滚动回退 uni.pageScrollTo（回调风格）
	uni.pageScrollTo({ scrollTop: props.scrollTop + scrollBy, duration: ..., success: () => {}, fail: () => {} })
}
```

回退路径用回调风格而非对象传参，是实测换来的：Web 端 `pageScrollTo` 传对象会抛 `The provided value is not of type 'ScrollToOptions'` 的 unhandled rejection——控制台看到这条日志才发现 demo 页是 scroll-view 结构，页面级 API 根本没被走到。

## 三、实测暴露并修复的三个 bug

组件写完只是开始，浏览器实测（12/13 场景通过，唯一未覆盖的 swipeable 手势需要 touch 输入通道，留待真机）暴露了三个静态检查永远发现不了的问题：

| bug | 现象 | 根因与修复 |
| --- | --- | --- |
| 协议未下发 | scrollspy 模式 m-tab 全部按普通模式布局 | TabsContext 的 `scrollspy` / `trackMode` 字段从未赋值——setup 中一次性下发（两 prop 声明期静态） |
| 基准线漂移 | 滚动联动判定恒为第 1 项 | 判定基准用了随内容滚动的 track top——改为视口固定线 `props.offsetTop` |
| paneEls 全空 | scrollspy 测量与点击定位失效 | m-tab 注册时内容因 lazyRender 未渲染，paneRef 为 null——新增 `updatePane` 补报，m-tab `watch(everRendered, { flush: 'post' })` 首次渲染后回填 |

第三个 bug 最典型：注册时序上 m-tab 先 mounted、m-tabs 后 mounted 才把 everSet 填满，pane 此刻才首次渲染——只有「先注册、后补报」两段式才能对齐这条链路。

## 四、m-image 点击预览

`preview` 开启后点击图片调用 `uni.previewImage` 弹出大图预览，全端可用，仅加载成功态响应；`preview-list` 指定预览图列表（不传或为空回退单图 `[src]`），起始索引自动取当前 `src` 在列表中的位置（找不到回退 0），`preview-current` 可显式指定。`preview` 开启不影响 `click` 事件透传，两者并存。

## 五、质量验证

- **Web 浏览器实测**：基础切换 / name 匹配（lazyRender 生效）/ 标签栏滚动 / 禁用拦截 / card / pill / color 派生底部条 / animated 转场 / 徽标 / before-change / options 禁用拦截 / scrollspy 平铺 + 滚动联动 + 点击激活，12/13 场景通过；控制台无运行时报错
- **未实测**：swipeable 手势跟手切换（浏览器无 touch 通道，真机验证）、pageScrollTo 页面级定位（演示页为 scroll-view 结构，App 端页面级滚动场景生效）
- **一致性**：`pnpm sync:uni-modules:check` 通过；`pnpm build:docs`（VitePress 死链检查）通过；VDOM 发布构建 m-tabs 零诊断（剩余 3 条 SSRSlot 为已知编译器噪音）
