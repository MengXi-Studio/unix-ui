# @meng-xi/unix-ui v0.5.2 发布：修复 m-calendar 首帧全量渲染月份

> v0.5.2 是一个只含一项修复的补丁版本：`switch-mode` 非 `none` 时，`m-calendar` 在挂载前瞬态回退渲染 `min-date ~ max-date` 的全部月份，宽范围（如 1900~2100）下首帧即渲染 2412 个月、约 10 万节点，微信小程序直接触发 `Dom limit exceeded`（[#15](https://github.com/MengXi-Studio/unix-ui/issues/15)）。本版本把兜底分支改为只渲染聚焦月，首帧节点数与日期范围宽度无关。

## 一、问题：日期范围越宽，首帧越容易压垮小程序

0.5.x 为日历新增了 `switch-mode="year-month"`（逐月切换）与 `year`（逐年切换）两种面板模式，本意是避免一次性渲染整月列表。但只要日期范围放得宽一些——生日、入职日期这类场景常见 `1900 ~ 2100`——首次打开就会出问题：

- 微信小程序控制台报 `Dom limit exceeded, please check if there's any mistake you've made.`
- 同时提示 `setData 数据传输长度为 36595 KB，存在有性能问题！`
- 日历面板空白或不可用；`switch-mode="none"`（滚动模式）下全量渲染属设计行为，但同样会超限
- Web 端不报错，但首次打开明显卡顿

复现只需一个 `m-calendar-popup`：挂载时 `show=false` 一切正常，把 `show` 置为 `true` 的第一次打开即触发。

## 二、根因：首帧渲染早于 `currentPanelMonth` 赋值

`switch-mode` 生效后的面板只渲染「当前月」，`visibleMonths` 依据 `currentPanelMonth` 过滤月份。但这个状态有两个时间点错位：

- `currentPanelMonth` 初始化为 `null`，注释标记为「挂载前瞬态」；
- 真正赋值发生在 `onMounted`（`initSelection` + `focusMonth` 之后），**晚于首帧渲染**；
- `visibleMonths` 在 `null` 时回退 `return months.value`（全量）作为兜底。

于是 `switch-mode` 生效后的第一帧必然走全量分支：`1900-01 ~ 2100-12` 正好 2412 个月，面板配置里 `months: Array(2412)`，节点数随范围宽度线性膨胀。点击切换月份后才回到单月渲染，但首屏已经卡死或超限。

这不是过滤逻辑算错，而是「兜底值」选错了：把「还没算出来」当成了「需要全部」。

## 三、修复：兜底只渲染聚焦月

`null` 兜底改为按聚焦月过滤，首帧即为 O(1) 的 42 个日期节点：

```uts
if (current == null) {
	// 挂载前瞬态：仅渲染聚焦月。宽范围（如 1900~2100）全量渲染会在小程序端触发 DOM 节点上限
	const focus = startOfMonth(focusMonth())
	return months.value.filter((m: CalendarMonth): boolean => isSameMonth(m.date, focus))
}
```

`focusMonth()` 本身已是「初始选中日期 → 今天 → min-date」的收敛结果，与 `onMounted` 中写入 `currentPanelMonth` 的值同源。因此首帧渲染的月份与挂载后定位的月份一致，不会出现「先渲染 A 月、再跳到 B 月」的二次刷新。

## 四、为什么不把初始化直接提前

issue 同时给出了方案 B（把 `initSelection` 与 `currentPanelMonth` 提前到 `setup` 同步执行）。没有采用，原因是：

- `currentInitDate()` 依赖 `v-model:value` / `default-date` / 今天三级回退，`initSelection` 在 `onMounted` 中还要处理 `multiple` / `range` 的集合初始化与主题色派生，提前到 `setup` 会把这些副作用挪到组件创建阶段，影响面比改一处兜底更大；
- `emit('month-show')`、`scrollToDate` 等挂载后行为仍必须留在 `onMounted`，提前初始化只能解决一半；
- 只改兜底分支即可让首帧有界，且对 `switch-mode="none"` 的全量渲染路径零影响，是改动最小、回归面最窄的方案。

方案 C（`slice(0, 1)`）也能限制节点数，但会先渲染 min-date 所在月再跳到聚焦月，产生可感知的闪动，不如按聚焦月过滤。

## 五、回归范围与验证

- **Web 实测**：日历弹层演示页正常渲染、无 Vite 错误覆盖层；打开 `single` 单选弹层后月份网格（星期行 + 日期）正常显示，控制台无报错
- **构建与一致性**：`pnpm sync:uni-modules:check` 通过，`pnpm build:docs` 通过
- **影响面**：仅 `m-calendar` 在 `switch-mode` 非 `none` 且 `currentPanelMonth` 为 `null` 的首帧路径；挂载后、`none` 滚动模式、日期选择与主题色派生逻辑均未改动；无 props / events / 插槽 / 主题变量变更
- **待复测**：微信开发者工具按 issue 步骤复测 `year-month` + 1900~2100 的首次打开（目标场景）；`year` 模式与其余小程序同链路

```bash
pnpm add @meng-xi/unix-ui@latest

```

无破坏性变更，纯内部渲染路径修正，升级后无需调整任何调用代码。
