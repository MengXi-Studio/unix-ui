# @meng-xi/unix-ui v0.7.1 发布：修复 m-icon 微信小程序端图标字体加载失败

> v0.7.1 是一个只含一项修复的补丁版本：微信小程序端任意 `m-icon` 挂载时会报 `loadFontFace:fail createDownloadTask:fail invalid url`，图标全部回退为默认字形（[#22](https://github.com/MengXi-Studio/unix-ui/issues/22)）。根因是内联字体的 `source` 只传了裸 base64，缺少微信要求的 CSS 资源地址格式包装；同时每个图标实例都会各自发起一次加载。本版本改为标准 `url("data:font/ttf;base64,...")` 形式，并用模块级标记保证全局只加载一次。

## 一、问题：小程序端图标全部不可见

微信小程序端进入任意使用 `m-icon` 的页面（含 `m-cell`、`m-button` 等内置图标的组件），控制台重复出现：

```
Error: MiniProgramError
{"status":"error","errMsg":"loadFontFace:fail createDownloadTask:fail invalid url"}
```

报错次数与页面上图标实例数一致，所有图标显示为默认字形（空白 / 方框）；H5 与 App 端正常。

## 二、根因：两处叠加

**1. `source` 不是合法的 CSS 资源地址**

`wx.loadFontFace` 的 `source` 必须符合 CSS 资源地址格式：

- 网络字体：`url("https://.../font.ttf")`
- 内联字体：`url("data:font/ttf;base64,...")`

组件此前直接传入 `M_ICON_FONT_BASE64`（以 `AAEAAAANAIAAAwBQRkZUTa` 开头的裸 base64），微信将其当作 URL 解析并尝试创建下载任务，因此报 `invalid url`。编译产物中可以看到该值被原样透传。

**2. 加载缺少全局复用**

`global: true` 已使 `family: 'm-icon'` 对整个小程序生效，但加载调用写在每个 `m-icon` 实例的 `onMounted` 里，页面上 N 个图标就会发起 N 次加载。即便地址修好，也仍然是重复调用。

## 三、修复

`packages/core/components/m-icon/m-icon.uvue` 的 `MP-WEIXIN` 分支：

```uts
// #ifdef MP-WEIXIN
onMounted(() => {
	if (mpFontState.loaded) return
	mpFontState.loaded = true
	uni.loadFontFace({
		global: true,
		family: 'm-icon',
		source: 'url("data:font/ttf;base64,' + M_ICON_FONT_BASE64 + '")',
		fail: () => {
			mpFontState.loaded = false
			console.warn('[m-icon] loadFontFace fail')
		}
	})
})
// #endif
```

两个要点：

- **地址包装**：拼接为 `url("data:font/ttf;base64,...")`，与 Web / App 端 `<style>` 内 `@font-face` 的写法语义一致，微信可正确解析内联字体；
- **失败复位**：`fail` 时把标记改回未加载并输出固定文案，后续图标实例仍可重试，同时便于排查（不阻断渲染，图标回退默认字形）。

## 四、为什么用模块级状态，而不是组件内标记

`<script setup>` 顶层声明的变量属于 **setup 作用域**，每个组件实例各有一份——写在组件里做「已加载」标记，N 个图标实例依然是 N 份独立状态，起不到去重作用。

因此新增 `components/m-icon/m-icon-mp.uts`，用模块级 `const mpFontState`（所有实例共享同一对象引用）承载加载状态。小程序编译产物中它是一个单例：`const o = new e({loaded:!1}); exports.mpFontState = o;`，所有 `m-icon` 实例引用同一份。

Web / App 端不进入该分支，标记对象仅作为空壳模块参与编译，无副作用。

## 五、回归范围与验证边界

- **影响面**：仅微信小程序端 `m-icon` 的字体加载；Web / App 端继续使用 `<style>` 内本地 ttf 声明，代码路径未改动；
- **API**：props / events / 插槽 / 主题变量均未变更，`m-icon` 对外行为不变；
- **已核对**：`mp-weixin` 编译产物的 `loadFontFace` 调用为 `source: 'url("data:font/ttf;base64,' + M_ICON_FONT_BASE64 + '")'`，且 `onMounted` 前置 `if (mpFontState.loaded) return`；
- **待复测**：微信开发者工具 / 真机打开任意含图标的页面，控制台不再出现 `invalid url`，图标正常显示；页面上多个图标只触发一次加载。
