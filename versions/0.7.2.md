# @meng-xi/unix-ui v0.7.2 发布：修复小程序端 picker-popup 工具栏空白、滚轮首次定位失效与选中态丢失

> v0.7.2 是一个只含修复的补丁版本，收敛三个微信小程序端问题：
> ① `m-picker-popup` / `m-date-picker-popup` / `m-time-picker-popup` / `m-lunar-picker-popup` 未传插槽时顶部工具栏空白、无法确认提交（[#24](https://github.com/MengXi-Studio/unix-ui/issues/24)）；
> ② 上述弹层首次打开（及复开）时滚轮停在首项 `1900-01-01` / `00:00`，不定位到传入的 `value`（[#25](https://github.com/MengXi-Studio/unix-ui/issues/25)）；
> ③ 复选框选中态没有白勾、加载 / 轻提示文案与徽标包裹内容不渲染——默认插槽在小程序端被误判为「未传」。
> 同时把 `m-checkbox` 族的默认形状由圆形改为方形，并修复小程序端勾选图标被样式隔离吞掉着色（黑勾）的问题。
> 三者均源于小程序端与 Web / App 的编译 / 渲染差异，业务侧无需改代码（默认形状变更见第四节）。

## 一、修复一：小程序端选择器弹层没有工具栏（#24）

### 现象

微信开发者工具打开任意 picker-popup 演示页，点击打开弹层后：

- 顶部只有一块空白区域，没有「取消 / 标题 / 确认」；
- 滚轮列可以滚动，但无法确认提交，取消也无入口；
- Web 与 App 端表现正常。

### 根因：两层叠加

**1. 空数组 ≠ null**

小程序端未传具名插槽时，`$slots['toolbar']` 得到的不是 `null`，而是一个空数组。原来的判断：

```html
<template v-if="$slots['toolbar'] != null" #toolbar>
```

在小程序端恒为真，弹层于是仍然把「空插槽」转发给面板，覆盖了面板的默认渲染。

**2. `<slot>` 默认内容被编译为 `wx:if`**

面板里的写法：

```html
<slot name="toolbar">
  <view v-if="showToolbar" class="m-picker__toolbar">...</view>
</slot>
```

小程序端被编译为：

```html
<block wx:if="{{$slots.toolbar}}"><slot name="toolbar"></slot></block>
<block wx:else>默认工具栏</block>
```

空数组是 truthy，`wx:if` 成立，默认工具栏永远不渲染。此外，弹层对子组件的插槽声明是编译期静态的（产物中 `u-s="{{['toolbar','title',...]}}"`），子组件 `$slots` 即使运行时未传内容也始终存在对应 key——因此只修弹层转发不够，面板层必须改为显式判断。

### 修复

新增 `packages/core/utils/slot.uts`：

```uts
export function slotHasContent(slot: any | null): boolean {
	if (slot == null) return false
	// #ifdef MP
	// 小程序端：插槽为节点数组，未传时为空数组；空对象取不到 length，同样视为未传
	const list = slot as any[]
	const len = list.length
	if (len == null) return false
	return len > 0
	// #endif
	// #ifndef MP
	// Web / App：插槽存在即视为已传入
	return true
	// #endif
}
```

- **弹层层**：所有 `$slots.x != null` 的模板守卫与脚本判断统一替换为 `slotHasContent($slots['x'])`（29 个组件文件、89 处模板守卫、23 处脚本判断），未传插槽不再向下转发；
- **面板层**：`m-picker`、`m-date-range-picker`、`m-time-range-picker`、`m-calendar`、`m-cascader`、`m-number-keyboard` 中带默认内容的 `<slot>` 改为显式分支：

```html
<template v-if="slotHasContent($slots['toolbar'])">
  <slot name="toolbar"></slot>
</template>
<view v-else-if="showToolbar" class="m-picker__toolbar">...</view>
```

## 二、修复二：小程序端弹层首次打开滚轮不定位到传入值（#25）

### 现象

`mp-weixin` 下打开 `m-date-picker-popup` / `m-time-picker-popup`：

- 首次打开时三列滚轮停在首项（`1900-01-01` / `00:00`），不定位到 `value`（如今天 / `'08:00'`）；
- 关闭后重新打开仍然错位；
- 直接点确认会把首项当作选中值回写。

### 根因：镜像位置被「提前写成已到位」

滚轮列（`m-date-picker-column`）的程序化定位链路有三处互相放大：

1. `requestScroll()` 在写 `scroll-top` 的同时**立即把内部镜像 `actualTop` 写成目标值**；
2. 弹层首帧挂载时面板处于隐藏态，滚动视口高度为 0，`scroll-top` 被忽略且不产生 `@scroll`；
3. 同值定位靠「先偏移 0.5px、`nextTick` 再归位」强制下发，而小程序端相邻两次 setData 会合帧，同帧内先加后减等效于无变化。

结果：第一次定位「看似成功」（镜像已是目标值、`scroll-top` 属性也已是目标值），实际位置仍在 0；后续 `resetSelection()` 再次请求定位时，`actualTop === target` 且属性值未变，直接跳过，弹层复开也无法自愈。

### 修复

**1. 镜像只认真实滚动位置**

`requestScroll()` 不再回写 `actualTop`，镜像一律由 `@scroll` 回灌的 `e.detail.scrollTop` 更新。吸附判定、受控值 watch 的「已到位跳过」、定位校验全部基于真实位置。

**2. 强制偏移改用定时器归位**

同值定位时先写 `target + 1`，50ms 后再归位 `target`——两次 setData 落在不同渲染帧，小程序端才会真正滚动；偏移 1px 视觉不可感知。

**3. 布局可用后再补一次定位**

- `requestScroll()` 内新增定位校验：120ms 后若镜像仍未到位（且期间用户未接管滚动），强制重发一次（只重试一层，避免隐藏态无限轮询）；
- 新增 `reposition()`：`m-picker` 以 `positionToken` 令牌下发给各列，弹层 `open` 时调用 `m-picker.reposition()`，让列在滚动视口真正可滚动后再对齐一次；`m-date-picker` / `m-time-picker` / `m-lunar-picker` 透传该方法，四个 picker-popup 在 `open` 时（`reset-on-open` 复位之后）统一调用。

## 三、修复三：小程序端默认插槽判定失效（选中态白勾 / 文案 / 包裹内容丢失）

### 现象

微信小程序端：

- `m-checkbox` 选中后只有一个实心蓝圆（或蓝方块），**没有白色勾**，观感接近单选；`indeterminate` 横杠也不显示；
- `m-loading` 的「加载中…」、`m-toast` 的消息文案、`m-badge` 被包裹的子元素、`m-number-keyboard-popup` 键盘上方内容区、`m-radio` / `m-checkbox` 独立使用时的标签文字，全部不渲染。

### 根因

`slotHasContent()` 按「数组长度 > 0」判定，只对**具名插槽**成立。默认插槽（写在组件标签之间的匿名子节点）在小程序端：

- 父级传了内容时 `$slots.default` 是**空数组**（子节点不进入数组元素，由匿名 `<slot/>` 直接渲染）；
- 未传时该 key 不存在。

长度判定因此恒为 `false`，把「已传」误判成「未传」。而组件内的默认内容又都写在 `<slot>` 的 fallback 里，fallback 被编译成 `wx:else`，于是勾选图标、加载文案、徽标子元素等整体消失。

### 修复

- 默认插槽一律改用 `slots['default'] != null` 判定（`m-loading` / `m-toast` / `m-badge` / `m-radio` / `m-checkbox` / `m-number-keyboard-popup`）；
- `m-checkbox` / `m-loading` / `m-toast` / `m-badge` / `m-radio` 的图标类默认内容改为与具名插槽同款的显式 `v-if / v-else` 分支（选中勾、`indeterminate` 横杠、`custom-class` 图标）；
- 勾选图标恢复后仍有第二个问题：**勾是黑色的**。原样式 `.m-checkbox__check { color: #fff }` 写在 `m-checkbox` 的 wxss 里、类名挂在 `m-icon` 内部节点上，小程序端自定义组件默认样式隔离（`isolated`），父组件样式无法命中子组件内部节点，`custom-class` 的着色被静默忽略。改为把 `color / font-size` 落在本组件的图标容器 `.m-checkbox__icon-wrap--checked` 上，靠**继承**穿透组件边界下发（继承不受样式隔离影响），并删除失效的 `.m-checkbox__check` 规则；
- `utils/slot.uts` 补充口径说明：`slotHasContent` 仅用于具名插槽，默认插槽按 key 存在性判定；
- **Android 云打包编译约束**：① 插槽判定原先直接写在模板里（`v-if="slotHasContent($slots['toolbar'])"`），Android 模板编译器会把「导入函数 + `$slots` 入参」生成成 `.invoke` 形式并报 `Unresolved reference 'invoke'` —— 24 个组件改为在脚本层用计算属性（`hasToolbarSlot` 等）求值，模板只引用布尔值；② Android 端 `<script setup>` 里的函数按声明顺序编译为**局部函数**，后声明的函数不能被先声明的函数调用 —— `m-date-picker-column` 的 `scheduleVerify` 已内联为 `requestScroll` 内的自递归校验。

## 四、变更：复选框默认形状改为方形

`m-checkbox` / `m-checkbox-group` / `m-checkbox-input` / `m-checkbox-popup` 的 `shape` 默认值由 `round` 改为 **`square`**（圆角方框），与复选框的主流视觉预期一致；需要圆形时显式传 `shape="round"`。

- 属视觉默认值变更：升级后未显式传 `shape` 的复选框会从圆形变为方形；
- 演示页「自定义形状」同时展示方形与 `shape="round"` 覆盖，文档默认值列同步更新。

## 五、验证

**小程序端（微信开发者工具，`mp-weixin` 产物）**

- #24：产物 `m-picker.wxml` 为 `<block wx:if="{{a}}"><slot name="toolbar"/></block><view wx:elif="{{b}}" class="m-picker__toolbar">`；运行时 `m-picker` 数据 `a=false / b=true / c/f/h=false`；`.m-picker__toolbar` 的 `boundingClientRect` 为 `390 × 44`；点击取消 / 确认均正常派发并关闭；四个 picker-popup 与范围 / 日历 / 级联 / 数字键盘弹层结构一致。
- #25：`m-date-picker-popup` 首次打开滚轮居中显示 `2026 / 11 / 21`（当天）；关闭后复开仍为 `2026 / 11 / 21`；`m-time-picker-popup` 受控值 `09:30` 打开后居中显示 `09 / 30 / 00`。
- 默认插槽：`m-checkbox` 选中项蓝圈 / 方块内出现白勾、`indeterminate` 横杠显示、禁用选中仍可见；`m-loading`「加载文案 / 自定义文字样式」卡片显示「加载中…」且无文案卡片无多余空白；`m-radio` 独立单选标签正常；`m-badge` 包裹模式子元素正常渲染；`m-number-keyboard-popup` 键盘上方内容区「请输入」正常。
- 默认形状与白勾：`m-checkbox` 未传 `shape` 时为方形，选中态为白勾 + 主题色实心填充；`shape="round"` 覆盖仍为圆形；`indeterminate` 为白色横杠；禁用选中保持降透明度下的白勾。

**Web 端（localhost:5174）**

- 日期选择弹层打开后三列居中 `2026 / 11 / 21`，定位与吸附、确认回写均正常；
- picker-popup 弹层工具栏「取消 / 选择产线 / 确认」与滚轮正常，点击确认关闭并输出 `confirm → 机加工一线`。

**工程校验**

- `pnpm sync:uni-modules` 一致；
- `mp-weixin` 编译成功；Web dev server 编译成功。

- `m-date-picker` / `m-time-picker` / `m-lunar-picker` / `m-picker` 新增实例方法 `reposition()`（弹层组合已自动调用，业务侧通常无需关心）。
