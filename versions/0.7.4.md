# @meng-xi/unix-ui v0.7.4 发布：修复小程序弹层默认工具栏被静态插槽吞掉

> v0.7.4 是一个只含修复的补丁版本，修复 [issue #29](https://github.com/MengXi-Studio/unix-ui/issues/29)：
> 微信小程序（uni-app x VDOM 模式）下 `m-picker-popup` 未传具名插槽时，顶部「取消 / 标题 / 确认」工具栏空白、无法确认选择。
> 根因不在插槽内容判定本身，而在**弹层组合组件把具名插槽静态声明给了面板**——面板拿到的永远是布尔 `true`，无法区分「页面没传」与「传了空内容」。
> 本次改为由弹层把真实的插槽存在性显式下发给面板，默认内容与自定义插槽两个方向同时恢复。无破坏性 API 变更。

## 一、现象

环境：HBuilderX 5.34（uni-app x，VDOM 模式）+ 微信小程序（mp-weixin）。

- `m-picker-popup` 打开后，顶部工具栏只占位、无「取消 / 标题 / 确认」文字，无法提交选择；
- 页面显式传 `#confirm` / `#columns-top` 时自定义内容能显示，但其余默认段落仍然缺失；
- 0.7.1 正常，0.7.2 / 0.7.3 必现；Web 与 App 端不受影响；
- 同根因影响所有「弹层组合组件 → 面板」的插槽转发：日期 / 时间 / 农历 / 日期范围 / 时间范围 / 日历 / 级联 / 数字键盘 / 密码输入 / 列表选择等弹层均存在默认内容被吞的风险。

## 二、根因：面板上的插槽被静态声明，恒为 `true`

弹层组件按 0.7.2 的方式做了「条件转发」：

```html
<template v-if="hasToolbarSlot" #toolbar>
	<slot name="toolbar"></slot>
</template>
```

在页面里这段探测是准确的：页面未传时 `slots['toolbar']` 为 `undefined`。

但小程序编译产物会在子组件标签上写入**静态插槽声明**：

```
<m-picker u-s="{{['toolbar','title','confirm','cancel','columns-top','columns-bottom']}}" ...>
```

`<template v-if>` 只控制插槽**内容**，不会阻止插槽**注册**。于是面板侧 `useSlots()` 里这 6 个 key 永远存在、值为布尔 `true`，面板的 `v-if="hasXxxSlot"` 默认内容分支永远不会走到——即使页面一个插槽都没传。

## 三、修复：显式下发插槽存在性（不做内容猜测）

新增内部工具 `slotActive(slot, presence, name)`：

```uts
export function slotActive(slot: any | null, presence: string | null, name: string): boolean {
	if (presence != null) {
		const names = presence.split(',')
		for (let i = 0; i < names.length; i++) {
			if (names[i] == name) return true
		}
		return false
	}
	return slotHasContent(slot)
}
```

- 弹层组件把自己准确的探测结果拼成「已传插槽名」英文逗号字符串，经内部 prop `slot-presence` 下发给面板；
- 面板改走 `slotActive`：有标记按标记判定，未下发标记（独立使用面板组件）时回退原有 `slotHasContent` 探测；
- 链式组合逐级原样下发：`picker-popup → m-picker`、`date/time/lunar-picker-popup → 面板 → m-picker`、`calendar-popup → m-calendar → m-calendar-panel`；
- 同时移除 0.7.3 中仅属推测的 `typeof slot == 'function' → true` 分支（多轮运行取证只观察到布尔 / `undefined` / 数组三种形态），避免把「假存在」判定为已传入。

`slot-presence` 为内部使用，默认 `null`；业务侧无需设置，也不在公开 API 承诺范围内。

## 四、影响范围

- 弹层侧（11 个）：`m-picker-popup`、`m-date-picker-popup`、`m-time-picker-popup`、`m-lunar-picker-popup`、`m-date-range-picker-popup`、`m-time-range-picker-popup`、`m-calendar-popup`、`m-cascader-popup`、`m-number-keyboard-popup`、`m-password-input-popup`、`m-select-popup`；
- 面板侧（10 个 + 1 个内部子组件）：`m-picker`、`m-date-picker`、`m-time-picker`、`m-lunar-picker`、`m-date-range-picker`、`m-time-range-picker`、`m-calendar`、`m-calendar-panel`、`m-cascader`、`m-number-keyboard`、`m-select`；
- 默认插槽与 Web / App 分支行为不变；未使用弹层、直接使用面板的写法也不受影响（无标记时回退原探测）。

## 六、从 0.7.3 升级

```bash
pnpm add @meng-xi/unix-ui@latest
# 将包内容拷贝覆盖 uni_modules/m-ui-x
```

- 无破坏性 API 变更，无需改业务代码；
- 若你在 0.7.2 / 0.7.3 上临时规避（放弃弹层内置工具栏、改用页面自带按钮），升级后可恢复使用默认工具栏与具名插槽；
- 弹层与面板之间新增的 `slot-presence` 为内部协议，请勿在业务中手动传值。
